# Poly Haven mass compatibility — 2026-10-28

`densityScale` is an optional, finite positive per-piece metadata value. Missing values default to 1. The collider density is `PIECE_DENSITY × balance.csv piece weight multiplier × densityScale`; the factor is applied once when a fresh Rapier convex hull is created. Replacement keeps its body's type scale while accepting a custom base density. Promotion uses the new type's scale. Reset recreates pieces through the same spawn path. Stage size changes hull volume normally, and weight upgrades remain additional mass based on the scaled hull mass. The new hull still determines center of mass and inertia. The pocket wall's King-derived radius is used for fixed obstacle geometry, not piece mass or density.

Run `node qa/polyhaven-model-2026-10-28/mass-compatibility-check.mjs` from the repository root. It builds real Rapier bodies from `git HEAD` original metadata and the new generated metadata. All six per-type original and new masses matched within relative `1e-5`. It also checked scale default 1 for old metadata, exact collider density factors, custom-density replacement, promotion, stage size and weight, reset, and that the King center of mass comes from the new hull. The printed mass values, rounded to six decimals, are Pawn .027423, Rook .044274, Knight .066776, Bishop .055475, Queen .080601, and King .102715 for both generations.

Checks run: focused check passed; `node web/src/tools/balance-physics-check.mjs` passed; `npm exec tsc -- --noEmit` in `web` passed. The balance test confirmed existing CSV weight, power, friction, restitution, replacement, and promotion behavior.

## Online compatibility finding (read only)

Old and new builds **can pass the initial online ready check**. The focused check computed identical initial state hashes from the old and new metadata. `online.ts` ready messages carry a `stateHash` and compare it before activation, but no model, collider, metadata, physics, or build version. `state-hash.ts` hashes only piece positions and rotations. The lobby code prefix remains `ca-online-1`. Turn hashes can detect divergence after play, but the `stateSnapshot` message carries only piece IDs, positions, and rotations. It cannot replace the other client's collider geometry or density. This permits old and new clients to start a match with different collision physics; later snapshot correction cannot make them physically compatible. A model or physics compatibility identifier in the online handshake should be handled before release. No online files were edited here.
