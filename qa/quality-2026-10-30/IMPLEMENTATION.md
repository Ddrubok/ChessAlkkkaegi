# 공통 게임 품질 개선 · 2026-10-30

로컬 검수 시점의 상태: 공통 코드 개선과 로컬 자동·브라우저 검수 완료. Android 실기기·실제 포털 대전·신규 이용자 검수는 미완료. 아래 빌드 ID와 해시는 커밋 전 검수 후보의 기록이다.

후속 요청에 따라 공통 코드·회귀 검사·검증 모델·선별한 QA 증거를 `develop` 푸시 대상으로 묶었다. 별도 crossplay 작업 트리의 기존 인증·초대 통합과 그 빌드 산출물은 이 커밋에 포함하지 않는다. CrazyGames 검수 기록은 별도 후보에 대한 로컬 결과이며 포털 재제출 기록이 아니다.

## 게임 의도와 범위

근거는 `Docs/체스 알까기 오류 수정과 CrazyGames 재심사 기획서_2026-10-30.md`와 사용자의 Google Play에도 같은 발전을 적용하라는 지시다. 마우스·Android 터치에서 기물을 당겨 놓고 상대를 장외로 밀어내는 행동과 결과를 명확히 한다. 목재 보드, CC0 기물, 흰색/검은색 진영, 턴제 규칙, 발사 세기·충돌 물리는 보존한다.

확정 결함: 스테이지 무승부 이후 상태 잔류, 매칭 취소 뒤 늦은 연결 인계. 기존 재현 보고서는 `qa/formal-verify-2026-10-29/FORMAL_VERIFICATION.md`에 보존한다. 카메라 크기·설명량은 개선 가설이며 같은 상태의 실행 전후로 평가한다. 숨겨진 iframe의 턴 시계는 기존 QA 기록과 현재 코드로 조사한다.

## 관찰할 성공 조건

- 무승부는 이전 성공분을 한 번 정산하고 메뉴·새 도전의 첫 승리까지 이어진다.
- 취소한 시도는 대전을 시작하지 않으며 오래된 정리가 새 연결을 닫지 않는다.
- 렌더링 지연이 턴 시간·물리 속도를 바꾸지 않는다. 로컬 일시정지와 온라인 턴 소유권은 유지한다.
- 첫 방문은 기존 연습에 바로 진입하고 스킵·재방문·초대 진입은 정확히 구분한다.
- 작은 화면에서도 목표·보드 경계·조준·메뉴가 남고, 저장된 입력 선호가 연습 때문에 바뀌지 않는다.

## 코드와 모델 검증

- 실제 소스의 결과 콜백과 새 도전 거래를 실행한 스테이지 검사: **55개 시작/무승부 조합**, 중복 지급, 패배/최종 클리어, 보드 준비 실패/재시도, 9개 언어 통과. UI 생성·보드 준비는 대역이며, 실제 물리 경기 55회를 했다는 뜻은 아니다.
- Lean: 81개 선언 검사, 변이 5/5 검출. 55개 모델 출력과 실제 소스 결과 JSON이 정확히 일치한다. 안전한 정수 범위·순차 흐름의 모델이며 저장소 장애나 물리를 증명하지 않는다. [모델 범위](stage-model.md)
- 매칭 취소: 지연된 open/untrack/remove, 즉시 재시도, 이전 오류, 중복 ready, Host/Guest 타이머, 친선전 연결 인계 통과. WebRTC/Supabase 대역을 사용했다.
- TLC: 4/4 설정, 5/5 도달 검사, 합계 186개 상태, 변이 5/5 검출. 한 매처·최대 두 시도 범위이다. 최종 타이머 보강은 런타임 회귀로 추가 확인했으며 타이머 수명 전체를 TLC로 증명한 것은 아니다. [모델 범위](matching.md)
- 턴 시계·타이머, 기존 `check:regressions`, `check:lobby`, `check:auth-interaction` 통과. 일부 대역 검사는 사용 중인 Vite HMR 포트 경고를 출력했지만 검사 자체는 종료 코드 0이었다.
- `check:lobby-motion`의 기존 문자열 일치 검사는 플랫폼 분기를 처리하지 못해 실패했다. 실제 퀘스트→주간→연습→모드 순서를 확인하도록 보정한 뒤 세 하위 검사 모두 통과했다. 게임 배치를 바꿔 검사에 맞추지 않았다.
- root와 crossplay에서 추가 매칭 회귀·대기열 검사 통과. crossplay의 실제 결과 콜백도 55개 스테이지 검사 통과.

기존 실패 모델/로그는 `qa/formal-verify-2026-10-29/`와 `stage-model-historical.*`에 보존했다. 최초 작업자 결과와 시각은 [자동 검사 기록](final-automation.md)에 있으며, 그 후 추가 수정은 이 문서의 결과와 아래 최종 빌드가 우선한다.

## 브라우저에서 실제로 확인한 범위

Edge, DPR 1, 로컬 앱, 외부 네트워크 차단 조건이다. 기물 좌표·선택·카메라 값을 읽는 관찰용 함수를 개발 응답에만 삽입했다. 물리 결과나 조작 함수는 주입하지 않았고 마우스/터치 이벤트로 발사했다.

- 821×462, 907×510, 1077×606, 1216×684, 1280×720, 1366×768, 1536×864, 1920×1080, 800×450 터치, 360×800 터치.
- 신규 연습 진입 → 건너뛰기 → 메뉴 → 새로고침 → 일반 스테이지 1 시작. 입력 선호 복원, 설명과 캔버스 분리, 초기 보드 네 모서리 노출, 페이지 오류 없음.
- 821×462 및 1280×720 마우스, 800×450 터치에서 실제 발사로 검은 폰이 장외 처리되고 2단계로 전환되는 것 확인.
- 당구식 기물 선택 후 1280×720→907×510 변경 시 선택 유지. 클래식 시점 회전 후 보드 모서리 노출 확인.
- 기존 821×462 캡처에서 보드 폭은 약 190px, 최종 수정 후 약 380px다. 같은 연습 배치의 화면 비교이며 모든 화면의 확대율을 뜻하지 않는다. [이전 화면](camera-baseline/821x462.png), [수정 화면](browser/821x462-en-tutorial.png)
- 초기에 자연스럽게 길게 당기면 아래 취소 버튼에 닿았다. 최종본은 작은 가로 화면의 기초 연습에 옆 취소 버튼과 넓은 캔버스를 적용했다. 180px까지 당겨 발사하는 검사와 일부러 취소 버튼 위에서 놓아 기물이 발사되지 않는 검사를 모두 통과했다. [최대 당김](browser/821x462-en-aim.png)
- 360px 프랑스어 표시 겹침은 발견 후 수정·재검사했다. [세로 화면](browser/360x800-fr-tutorial.png)

상세값/캡처: [브라우저 결과](browser/results.json). 10가지 화면 크기에서 9개 언어를 나눠 12개 경우를 실행했다. [실제 입력 흐름 녹화](browser/firstplay-mouse-1280.webm)는 자동 조작 기록으로, 신규 이용자 반응이나 60초 사람 플레이 검사를 대신하지 않는다. 9개 언어 문구 계약 검사와 각 언어별 실행 결과를 별도로 기록했다.

## 최종 빌드와 동일성

공통 수정은 root `develop`와 별도 CrazyGames crossplay 작업 트리에 모두 반영했다. crossplay의 기존 로그인·초대·SDK·네트워크 통합은 보존했다. 원본 백업과 병합 기록은 `.orca/quality-crossplay-integration-2026-10-30/`에 있다.

| 후보 | 최종 출력 | build ID | 크기 |
|---|---|---|---|
| 일반 웹/Android 공통 웹 코드 | root `qa/quality-2026-10-30/web-candidate-dist/` | `c75b00d16d46-dirty-20261029175351` | 109개, 9,123,317 bytes |
| CrazyGames crossplay | crossplay 작업 트리 `qa/quality-2026-10-30/crossplay-candidate-dist/` | `245aaa99726d-dirty-20261029175356` | 109개, 6,949,779 bytes |

`dirty`는 미커밋 작업을 포함한다는 뜻이다. 두 후보는 같은 Git 커밋으로 간주하지 않는다. [일반 웹 해시](final-web-receipt.json), [CrazyGames 해시](final-crossplay-receipt.json), [수정 소스 해시](source-snapshot.json)에 상세 내역이 있다. 이 표의 `*-candidate-dist`만 최종 후보이며 앞서 만든 나머지 빌드 폴더는 중간 산출물이다.

최종 빌드는 기존 chess/balance 사전 검사와 TypeScript를 포함해 성공했다. CrazyGames 패키지 검사는 0 findings. 실제 **최종 압축 전 파일**을 별도 로컬 서버에서 다시 열어 신규 연습·건너뛰기·재방문을 확인했다. CrazyGames는 합성 SDK로 `loadingStop`, 신규 연습의 `gameplayStart`, 초대/Instant 진입 시 연습이 끼어들지 않는 것을 확인했다. [패키지 실행 결과](packages/results.json)

SDK 모의 검사는 실제 포털 QA 완료를 뜻하지 않는다. 작업자의 백그라운드 preview 실행이 자동 검토에서 거절됐지만, 이후 상위 작업에서 자격증명이 필요 없는 로컬 정적 파일 서버로 최종 패키지 검사를 완료했다.

## 재실행 방법

root `web/`에서:

```powershell
node src/tools/stage-run-result-check.mjs
node src/tools/match-cancel-check.mjs
node src/tools/turn-clock-check.mjs
node src/tools/turn-timer-check.mjs
npm.cmd run check:regressions
npm.cmd run check:lobby
npm.cmd run check:auth-interaction
npm.cmd run check:lobby-motion
```

로컬 Vite가 5283에서 실행된 상태에서 root에서 `node web/src/tools/camera-fit-check.mjs`. 이 브라우저 스크립트는 설치된 Edge와 `.orca/ui-check`의 Playwright를 사용한다. 최종 패키지 검사는 `node .orca/quality-package-smoke.mjs`.

빌드 명령은 일반 웹 `npm.cmd run build -- --outDir ../qa/quality-2026-10-30/web-candidate-dist`, crossplay `npm.cmd run build:crazygames -- --outDir ../qa/quality-2026-10-30/crossplay-candidate-dist`였다. crossplay에는 기존 운영 publishable 설정을 프로세스 환경으로만 전달했다. 키 값은 문서/로그에 쓰지 않았다. 재빌드는 새로운 출력 폴더 이름을 사용하고 검사 경로도 맞춰야 한다. `.orca/quality-final-build.mjs`는 이미 있는 후보를 덮어쓰지 않도록 중단한다.
