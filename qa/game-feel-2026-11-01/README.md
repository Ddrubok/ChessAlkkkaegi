## 실행한 검사

- `npm run check:regressions`: 전체 통과. 이후 충돌 정규화·작은 화면 배치 수정은 아래 관련 검사로 다시 확인.
- `npm run check:game-feel`: 최종 소스 통과. sound/aim/impact 검사를 묶고 기존 regressions에도 연결했다.
- `npm run check:lobby-motion`, `node src/tools/cards-headless-check.mjs`, `node src/tools/queen-overdrive-check.mjs`: 통과.
- `npm run build:staging`: 최종 소스 타입 검사와 빌드 통과. 기존 청크 크기·동적 import 경고는 남아 있다.
- `strike-hud-browser-check.mjs`: 844×390 터치에서 타점 선택, 당김, 취소, 재진입, HUD 위 발사, 룩·퀸 및 카메라 입력 검사 통과.
- `browser.mjs`: 1280×720 마우스, 844×390 터치, 390×844 터치에서 실제 튜토리얼 포인터 입력 검사. 세 화면 모두 런타임 오류 0, 발사 후 다음 단계 진입.
- 실제 Rapier 동일 초기 상태를 피드백 없이/30fps 묶음/60fps 묶음으로 실행해 최종 물리 상태 일치 확인.

| 1280×720 | 88% | 9.680000 | 추가 충전 없음 | 0.800 |

강도 지표는 소리/화면 효과 선택에만 쓰는 0~1 값이며 게임 파워가 아니다. 브라우저는 Edge headless 터치 에뮬레이션이다. 관찰용 runtime 참조만 노출했고 입력·물리는 바꾸지 않았다. 외부 통신을 막았으므로 이 검사는 온라인 대전 증거가 아니다. 녹화 파일에는 오디오가 없다. headless 프레임 시간은 실제 휴대전화 성능으로 해석하지 않는다.

## 검수 중 수정한 문제

1. Rapier가 접촉 쌍을 뒤집어 전달할 때 정상 충돌이 접근 속도 필터에 걸렸다. `flipped` 방향을 반영하고 콜라이더 생성 순서를 뒤집은 재현 검사를 추가했다.
2. 회전 접촉의 속도 계산 기준을 body origin에서 실제 `worldCom()`으로 바꿨다. 원점만 다른 동일 질량 중심 사례가 같은 결과를 내도록 검증했다.
3. SFX 0/음소거에서 음악만 줄어드는 경로를 차단했다.
4. 루프 중 온라인 스냅샷이 도착해도 같은 프레임의 이전 접촉 표시와 발사 복원을 정리한다.
5. 작은 가로 화면에서 상한 표시 때문에 발사 취소 영역과 테두리가 겹쳤다. 기존 안내 칸 안에 상한을 배치하고 간격을 확보한 뒤 터치 검사를 다시 통과했다.
6. 실제 폰 질량보다 높던 효과 강도 계산의 최소 질량 보정값을 낮췄다. 약한 충돌과 강한 충돌을 구분하며 물리 질량은 변경하지 않는다.

독립 Sol 소스 검토에서 1·2번을 발견했고 실패 재현 후 수정했다. 검토 최초 기록은 로컬 `review.txt`에 보존했다. 브라우저 비교 중 공유 Vite 캐시로 Three 인스턴스가 중복된 검사 환경 문제는 기준/개선 캐시를 분리해 해결했다.

## 직접 확인할 순서

개발 주소: https://chessalkkagi-dev.pages.dev/ . 배포 후 새로고침해 확인한다.

1. 튜토리얼 또는 연습에서 천천히 당겼다가 멈추고 되돌린다. 소리가 현재 당김에 반응하고 유지한다고 더 충전되지 않는지 확인한다.
2. 룩 중앙/회전, 퀸 중앙/회전으로 100%와 150% 상한을 비교한다. 취소했을 때 발사 효과가 남지 않는지 확인한다.
3. 약한 스침과 강한 정면 충돌을 비교한다. 강한 충돌의 짧은 소리와 반동이 도움되는지, 거슬리거나 조준을 방해하지 않는지 확인한다.
4. 상대 기물과 내 기물을 각각 떨어뜨려 소리와 남은 수가 구분되는지 확인한다. 기물이 넘어지기만 한 경우 탈락으로 안내하면 안 된다.
5. 같은 볼륨에서 스피커/이어폰을 각각 확인하고 동작 줄이기·SFX 0도 비교한다. 이후 연결된 Android와 실제 온라인 한 판을 확인한 뒤 main 반영 여부를 판단한다.

새 외부 자산이나 의존성은 추가하지 않았다. 기존 효과음과 자체 WebAudio 합성음을 사용하며, 기존 자산 전체의 라이선스를 이번 작업에서 새로 감사한 것은 아니다.

## 재실행

`web` 폴더에서:

```sh
npm run check:game-feel
npm run check:regressions
npm run build:staging
```

루트에서 `node qa/game-feel-2026-11-01/browser.mjs` 실행. Playwright는 기존 `.orca/ui-check` 설치 또는 `PLAYWRIGHT_MODULE`의 모듈 URL을 사용한다. 기준 비교는 `QA_BASELINE_ROOT`를 기준 커밋 worktree의 `web` 경로로 지정하고 `--baseline`으로 실행한다. 이 관찰용 스크립트는 빌드에 포함되지 않는다.

상세 로그·PNG·WebM은 로컬 `qa/game-feel-2026-11-01/`에 보존한다. 저장소에는 이 문서, 재실행 스크립트와 소스 검사를 포함하며 대용량 녹화와 Vite 캐시는 포함하지 않는다.
