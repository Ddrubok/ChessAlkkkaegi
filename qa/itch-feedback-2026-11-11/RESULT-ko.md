# 체스 알까기 플레이어 피드백 적용 결과

2026-11-11 · develop 작업 폴더 · 로컬 적용 및 검증

**약한 샷을 조절하는 입력, 파워 연습, 무승부 재경기, 강화 설명, 온라인 진입 안내를 수정했다.** 공개 itch.io 업로드·운영 DB 변경·Git 커밋/푸시는 수행하지 않았다. 기존 작업 폴더의 itch 로그인·저장·매칭 변경은 보존했다.

## 실제로 달라진 점

| 기획 항목 | 적용 결과 |
| --- | --- |
| C01 마지막 입력 | 마우스를 놓은 순간의 좌표로 세기와 방향을 다시 계산한다. 예를 들어 마지막 이동이 80%여도 40% 위치에서 놓으면 40% 요청을 보낸다. 취소·범위 밖 release는 먼저 차단하며 중복 발사하지 않는다. |
| C02 정밀 조절 | 설정 → Controls/조작에 180·240·360px 선택과 복원을 추가했다. 길게 당기는 설정에서는 같은 위력을 만들기 위해 더 멀리 움직이므로 작은 힘을 세밀하게 조절할 수 있다. 최대 위력 자체는 바꾸지 않았다. 기본값은 180px로 보존했다. |
| C03 표시 | 기존 HUD에 25·50·75·100%, 허용 기물에는 150% 참조 눈금을 표시한다. 현재 방향에서 화면 가장자리 때문에 최대 세기에 못 닿으면 경고한다. 당구식의 아래 HUD 공간도 실제 발사 가능한 가로 범위 안에서만 계산한다. |
| C04 파워 연습 | 첫 샷 성공 후 선택형 약한 샷 연습을 제공하고, 메뉴 → Tutorial에서도 바로 진입한다. 실제 30~50% 발사가 목표이며 장외나 승리가 필요하지 않다. 틀리면 실제 세기를 알려주고 같은 배치를 다시 준비한다. 연습은 도전 저장·포인트·튜토리얼 완료 기록을 변경하지 않는다. |
| C04 무승부 | solo 스테이지 무승부에서는 현재 단계·강화·런 누적 상태를 보존한다. 기본 버튼으로 같은 단계를 다시 하며, 무승부 보상이나 카드 재추첨은 없다. 메뉴·새로고침에서도 단계 시작으로 복원할 체크포인트를 남긴다. |
| C05 난도 | 4~6단계 실제 수치와 물리 조건을 기록했다. 조작 개선 후 사람의 실패 원인을 비교하기 전이므로 거대 폰 도입 시점이나 적 스탯은 바꾸지 않았다. |
| C06 강화 | 카드 보너스의 현재→다음 값을 '교체'로 표시한다. 다음 단계의 실제 크기·질량·초기 속도도 별도로 계산해 제공하고, 변화 없는 값은 안내한다. 중량의 '같은 파워에서 이동거리 감소'라는 설명을 제거했다. 질량 증가와 발사 속도·최종 이동거리를 구분한다. |
| C07 펼침 | 일반 카드의 중복 Details를 제거했다. 거대 폰의 제거 대상, 누운 시작의 예외처럼 추가 정보가 있을 때만 구체적인 제목으로 펼친다. 선택은 한 번만 적용하며 로딩 실패 시 재시도할 수 있다. |
| C08 온라인 | 게스트 방 코드와 로그인 후 자동 매칭을 구분해 설명한다. 클래식·전략은 서로 다른 큐임을 알리고, 실제 다른 대기자가 0명일 때 기다리거나 친구를 초대할 수 있다고 안내한다. 인증·대기열·랭크 정산 규칙은 유지했다. |
| C09 벽 | 3단계에 두 번의 새 접촉 후 파괴·균열·낮은 벽의 규칙을, 7단계에 불파괴 벽 규칙을 안내한다. 1단계에는 폰 3 대 3이며 한 발 제한이 아니라는 설명을 추가했다. 안내는 닫거나 첫 발사 시 정리된다. |
| C10 자세 | 실제 3D 물리로 자세·중심/표면 타격을 비교했다. 검사한 조건에서 오류가 재현되지 않아 임의의 누운 자세 속도·마찰 배율을 추가하지 않았다. |
| C11 타격감 | 기존 충돌음·음악·공통 물리 상수·시뮬레이션 배속을 보존했다. 조작 개선을 이유로 새 파티클이나 큰 화면 흔들림을 추가하지 않았다. |

새 안내는 한국어·영어를 제공하며 다른 언어에서는 영어 안내로 표시한다. 기존 지원 언어 설정은 유지한다. 당김 거리 설정은 이 기기의 로컬 환경설정이며 계정 진행 저장 revision에 포함하지 않는다.

## 실행한 검증

- TypeScript 및 **itch.io·CrazyGames·일반 웹 빌드 통과**. itch/CrazyGames 산출물 검사 통과. CrazyGames에 itch 인증 주소가 남던 문제는 플랫폼 조건을 분명히 해 해결했다.
- [실제 브라우저 결과](browser-result.json): 19개 기록 항목 통과, 페이지 오류 0건. 1366×768에서 첫 샷 → 선택형 연습 → 40% 실제 샷 성공 → 70% 실패 안내 → 재연습 → 메뉴 복귀를 실행했다. 유효한 로컬 QA용 5단계 체크포인트·포인트·튜토리얼 기록이 반복 연습 후 동일함을 확인했다. 외부 서버 요청은 허용하지 않았다.
- 설정의 선택·복원과 800×450·390×844 화면 범위를 확인했다. 추가 기존 설정 검사에서 320px 폭, 키보드 포커스 가두기, 치장품 임시 선택 보존이 통과했다. 작은 화면 브라우저 검사는 실제 휴대전화 하드웨어 검사를 대신하지 않는다.
- 실제 `main.ts` 결과 콜백을 실행하는 검사에서 1~10단계 무승부, 중복 결과, 같은 단계 재경기, 보드 준비 실패/재시도, 체크포인트 재읽기를 확인했다. 보드 생성과 결과 UI는 해당 검사에서 대역을 사용하며, 실제 경기를 끝내 만든 무승부 영상은 아니다.
- 파워 입력 검사에서 최종 move/up 좌표 불일치, 중복 release, 설정 변경 시 취소, 100/150% 경계와 방향별 유효 범위를 확인했다. 기존 클래식 취소·터치 검사도 통과했다.
- 카드 DOM 검사에서 일반 카드 펼침 제거, 등급 교체 표시, 실제 제거 폰 수, 특수 설명, 선택 중복 방지, 실패 재시도를 확인했다.
- [실제 Rapier 측정](physics-results.json): 자세/타점/세기 18회, 벽 단계 6개, 경계 접근 3개. 선/기울임/누움의 같은 목표 초기 속도와 다른 회전·이동, 두 번의 새 접촉 후 벽 제거, 불파괴 벽 유지, 낮은 벽 위 통과가 관찰됐다. 렌더 메시와 충돌체의 대응은 공통 정의를 확인했으며 전체 화면의 디버그 겹침 캡처를 만든 것은 아니다.
- 카드 크기·질량·초기 속도의 1·2·5등급 **9개 전후값**을 실제 물리 생성/발사값과 비교해 일치했다. 아직 모든 기물·연구·상한 조합을 전수 검사한 것은 아니다.
- 인증 클라이언트, 매칭 Presence·취소, 정산 클라이언트, solo 체크포인트, 기존 비solo 런 결과, 조준 피드백과 소리 계약 검사를 통과했다. 네트워크 검사에 모의 서버가 포함되므로 실제 두 계정 경기 완료·점수 정산의 증거로 쓰지 않는다.
- 기존 결과 검사에는 non-solo 검증이라는 범위를 명시하고 누락된 UI 대역을 보완했다. 기존 설정 검사의 고정 포트 의존성을 제거해 독립 로컬 서버로 실행했다.
- 독립 Sol 코드 검토에서 진행을 막는 정확성 결함은 보고되지 않았다. 최종 화면 확대·접근성·후반 카드 체감의 사람 검수는 남아 있다.

자동 검사·브라우저 입력 성공은 실제 이용자가 더 편하다고 느꼈다는 뜻은 아니다. 240px 기본값 채택, 부분 파워 오차 비교, 5단계 난도와 벽·누운 자세의 체감은 피드백을 준 이용자의 재검수가 필요하다.
