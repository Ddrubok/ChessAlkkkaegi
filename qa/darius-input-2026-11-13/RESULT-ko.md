## 적용한 변경

- 당겨서 놓는 조작을 유지했다. 마우스·펜은 `p=min((d/D)^2.4, 기물 상한)`을 사용한다. 지수는 포인터를 누를 때 고정한다. 터치는 기존 선형 변환·기존 화면별 거리 제한을 유지한다.
- D는 저장된 180/240/360px와 화면별 안전 범위 중 작은 값이다. 150%에 필요한 당김은 `D × 1.5^(1/2.4)`다. 넓은 캔버스(가로/세로 ≥1.5)는 짧은 변의 18%, 그 외는 15%를 전체 150% 당김 예산으로 사용한다. 기물·위치·방향별 감도 보정은 없다.
- 전체 보드 맞춤 여백을 18%→15%로 조정했다. 보드 투영 경계를 기준으로 구도를 맞추고, 캔버스 높이 3.5%의 추가 상단 여유를 확보한다. 월드 보드 중심의 줌 축은 유지한다. 선택 말별 클래식 자동 줌은 추가하지 않았다.
- 클래식·당구식 파워, 최종 release, 도달성 경고, 튜토리얼 제스처가 같은 정방향·역방향 계산을 사용한다. 표시 파워와 발사 요청을 분리하지 않았다.
- 모드 전환·선택 말 접근·타점 편집 때 투영 오프셋도 기존 카메라 전환과 함께 보간한다. 자유 당구식·타점 근접 화면에는 보드용 오프셋을 남기지 않는다.
- 설정은 희망 거리와 실제 100% 거리를 계속 표시한다. 화면 제한 때문에 실제값이 같으면 기존 안내를 유지한다. 발사 물리·기물 특성·네트워크 요청 형식·보상은 변경하지 않았다.

## 후보 선택과 발견한 문제

1. 실제 캔버스와 보드 투영을 조사했다. 선형 180/240px를 그대로 적용하면 모든 가장자리의 150% 공간을 확보할 수 없는 조합이 있어 기본 채택하지 않았다. [정적 기하 검토](geometry-study.md)는 초기 후보의 계산 기록이며 실제 브라우저 검증과 구분한다.
2. 20% 예산·제곱 곡선의 초기 후보는 일반 잡기 지점에서는 통과했지만, 카메라를 반대로 돌리고 최대 확대 후 먼 쪽 말의 위를 잡는 검사에서 화면 밖 release가 확인됐다. [실패 기록](after-04/result.json)을 보존한다.
3. 상단 여유·18% 예산으로 경계를 고친 제곱 후보는 [기능 검사](after-05/result.json)에 통과했다. 그러나 1366×768 전체 대국 캔버스에서 30% 반경이 45.56px로 초기 50px 목표에 미달했다.
4. 전체 150% 공간 예산을 늘리지 않고 낮은 파워에 더 긴 구간을 배정하도록 지수를 2.4로 조정했다. 최종 [after-06 결과](after-06/result.json)의 데스크톱 전체 대국 캔버스에서 반경은 1920×1080: 80.82px, 1366×768: 52.10px로 목표를 충족했다. 제곱 곡선의 단순 채택과 구분되는 수치 조정이다.
5. [독립 소스 검토](independent-review.md)가 지적한 모드 전환 후 남는 투영 오프셋은 전환 시작·종료 값의 보간과 종료 시 재동기화로 수정했다. 최종 브라우저에서 자유 당구식·선택·타점 편집은 오프셋 없음, 클래식 복귀는 올바른 오프셋 복원을 확인했다. 해당 검토 문서는 수정 전 지적을 보존한다.

높은 파워 구간에서는 선형보다 픽셀당 변화가 커질 수 있다. 저파워에서 얻는 이득과 고파워 조절 감각의 교환은 실제 사용자 과제로 확인해야 한다. 새 곡선을 모든 구간의 정확도가 검증된 개선으로 표현하지 않는다.

## 실행한 검사

- 최종 소스의 `playtest-frame-check.mjs`, `itch-power-controls-check.mjs`, `touch-input-headless-check.mjs` 통과. 화면 방향·거리·경계·최종 up·중복 release·작은 입력·약하게 되돌린 샷·터치 선형 동작 등을 각 검사 범위에서 확인했다.
- 최종 소스로 `npm run check:regressions` 통과. 원시 로그: `.orca/tasks/darius-regressions-final.log`.
- `npm run build`, `build:itch`, `build:crazygames` 통과. TypeScript 검사와 각 prebuild 검사를 포함한다. 기존 큰 번들 경고는 남아 있다. `itch-build-check.mjs`도 통과했다.
- [최종 브라우저 검사](after-06/result.json): 1920×1080·1366×768·800×450·390×844, 32개 기물의 로컬 2인 배치, 보이는 실제 잡기 지점, 8방향 룩/퀸 150%, 먼 쪽 왕·퀸·룩의 위쪽 잡기, 클릭·떨림·리사이즈 취소·1회 발사·반복 up·카메라 전환 등 **468개 자동 assertion 통과**. 실제 사람의 468개 플레이 시험을 뜻하지 않는다.
- [계측을 주입하지 않은 itch 빌드 검사](compiled-final/result.json): 새 Edge 컨텍스트에서 튜토리얼의 실제 손짓 끝점으로 당겼다가 놓기 → 첫 샷 완료 → 1단계 진입. 페이지 오류 0, 테스트 전역 변수 없음. 빌드 ID `c2649005f455-dirty-20261113032944`.
- 브라우저는 로컬 정확한 origin만 허용, Service Worker 차단, WebSocket 종료 정책으로 실행했다. 서버·계정·랭크·보상 관련 운영 쓰기를 수행하지 않았다. 소스 해시가 실행 중 바뀌지 않았는지 각 결과에 기록했다.
