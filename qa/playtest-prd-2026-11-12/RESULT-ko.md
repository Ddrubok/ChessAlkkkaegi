**‘당겨서 놓기’를 유지하며 미세 이동 오발 방지, 화면별 고정 당김 거리, 보드 여백, 선택 기물 안내를 구현했다.** 기존 강화·물리·무승부·매칭 처리에는 새 규칙을 추가하지 않고 회귀 검사를 실행했다. 기획 전체의 사용자 수용 완료를 뜻하지 않는다.

## 재현과 수정 근거

- [입력 기준 실행](baseline-2026-11-12T06-07-17-798Z/result.json): 제자리 클릭은 요청 0회였지만 1px 움직인 release는 발사를 요청했다. 실행 전후 소스 해시는 동일했다. 이 시점에는 화면 구도 작업 일부가 이미 반영돼 있어 **입력 오발 비교의 기준**으로만 쓰며, 원래 카메라 구도의 before 캡처라고 부르지 않는다.
- [최종 브라우저 실행](after-2026-11-12T06-35-09-488Z/result.json): **233개 assertion 통과, 페이지 오류 0건, 검사 대상 소스 변경 0건**. 로컬 Vite에서 테스트 전용으로 내부 런타임·발사 요청을 관찰하고, 실제 Playwright 포인터/키보드를 사용했다. 전체 보드 비교는 실제 reset 함수를 테스트 코드에서 호출한 준비 상태이며 메뉴 진입 과제는 아니다.
- 클래식: **1366×768·800×450·390×844**, 양쪽 룩·퀸·킹 4개 선택점 × 8방향 = **96개 조준**. 해당 기물 100/150% 값, 캔버스 안 release·취소 영역 밖임을 확인하고 ESC로 취소했다. 96개를 모두 실제 발사한 것은 아니다.
- 당구식: 위 3개 크기에서 룩을 다시 선택하고 빨간 점을 아래로 당겨 **150% 실제 release 요청 1회씩** 확인했다. 모드 전환이 선택을 초기화한다는 기존 규칙을 테스트 준비에 반영했다.
- 조준 중 A 키를 눌러도 카메라 좌표가 고정됐고, 리사이즈 후 release는 발사하지 않았다. 설정의 거리 버튼 초점은 리사이즈 후 유지됐다.
- 작은 화면에서 실제 당김 거리가 짧아지자 기존 튜토리얼 화살표의 24px 표시 문턱 때문에 방향 표시가 사라질 수 있었다. 화살표·고리 크기도 실제 예시 거리와 함께 줄이도록 수정하고, 새 컨텍스트의 800×450·390×844 첫 화면에서 표시를 확인했다. [800×450](after-2026-11-12T06-35-09-488Z/first-cue-800x450.png), [390×844](after-2026-11-12T06-35-09-488Z/first-cue-390x844.png).
- 1280×720·1920×1080은 스테이지 화면/좌표를 추가 기록했다. 이 두 크기에서 96개 조준과 같은 최대 파워 행렬을 실행했다고 확대하지 않는다.
- [최종 itch 산출물 실행](built-2026-11-12T06-36-19-381Z/result.json): 테스트용 런타임 노출 없이 생성된 `dist-itch`를 열어 실제 50% 당김·놓기로 첫 샷 완료 화면에 도달했다. 페이지 오류 0건.

브라우저는 새 컨텍스트·Service Worker 차단, 정확한 로컬 origin 허용 목록, 외부 요청 및 WebSocket 차단으로 실행했다. 실제 로그인·계정 저장·운영 보상·온라인 서버 정산은 호출하지 않았다.

## 남은 수용 판단

1. **정밀 조절·손맛은 미검증.** 캔버스가 작으면 실제 거리가 대략 30~70px대로 줄고 180/240/360 선택지가 같은 값이 될 수 있다. 설정에 이를 표시했지만, 기존 180px보다 부분 파워 조절이 좋아졌다는 결과는 없다. 사용자 반복 파워 과제와 보드 식별·오선택 비교 후 구도·거리 정책을 채택/조정해야 한다.
2. 모든 기물·자세·양 진영·카메라 각도·125/150% 배율·실제 터치 하드웨어의 도달성은 미검증이다. 확인한 초기 배치·시점의 성공만으로 PF-R02 전체 완료를 선언하지 않는다.
3. 선택 기물 안내의 이해·전술 선택 변화, 별도 특성 연습 진입, 첫 이용자의 온라인 발견성은 남아 있다. 폰 승격·킹 특수기의 실제 모드 차단을 이 작업에서 해제하지 않았다.
4. 실제 두 로그인 계정의 전체 경기·정산, 1·5단계 실패 유형, 강화 체감·벽/누운 기물의 인간 평가, 실제 소리 청취·Android 기기 검수는 남아 있다.

재실행: 루트에서 `node qa/playtest-prd-2026-11-12/browser-check.mjs after`, 생성한 itch 빌드에서 `node qa/playtest-prd-2026-11-12/built-smoke.mjs`. 매 실행은 새 폴더를 만들며 기존 실패·캡처·원본 보고서를 덮어쓰지 않는다. 후속 요청으로 develop에 소스·기획·선택한 QA 근거를 커밋·푸시한다. 공개 게임 업로드는 포함하지 않는다.
