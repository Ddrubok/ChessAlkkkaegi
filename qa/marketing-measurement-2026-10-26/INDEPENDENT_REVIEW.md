## Definite findings

1. **Second-match rate has an inflated denominator filter.** The plan defines the denominator as all environments that normally completed their first regular match (plan §8, line 293). `scripts/marketing-metrics.mjs:81` instead uses `firstSessionFinish`, which requires both the start and finish to carry the first session ID (`:56-57`). A first match completed after a 30-minute inactivity boundary remains a normal first completion, but disappears from this denominator. Example: one such completion and no second match should report `0/1`; the current report gives `0/0`. Keep the same-first-session condition for the numerator; use `firstFinish` for the denominator.

2. **Two specified friend rates are absent from the report.** The plan requires participant-based friend rematch rate and room-based invite join rate (plan §8, lines 294-295). `scripts/marketing-metrics.mjs:106-108` exposes only event counts and analytics-ID counts for `invite_created`, `invite_joined`, and `rematch_start`; neither rate or its denominator appears elsewhere in the returned report (`:96-123`). A single room can have two participant reports and repeated invitation events, so these counts cannot substitute for either rate. Add distinct invite-room keys for created/joined rooms, and distinct participant/match pairs for friend rematches, with explicit numerators and denominators. Preserve expired created rooms in the invite denominator.
