# 체스 알까기 itch 플레이어 피드백 개선 기획서

2026-11-11 · 개발 및 QA 실행용 · **상태: 주요 변경 구현 및 로컬 검증 완료, 사용자 비교 검증 대기**

후속 적용 요청에 따라 입력·연습·무승부 재경기·강화 설명·온라인 안내를 구현했다. 아래 사양의 조건부 시험값을 모두 기본 규칙으로 바꾼 것은 아니다. **기본 당김 거리 180px와 기존 물리·5단계 난도는 유지**한다. 항목별 적용 결과와 스크린샷은 [구현 및 검증 결과](../qa/itch-feedback-2026-11-11/RESULT-ko.md)를 참고한다.

## 1. 목표와 결정

**부분 파워를 의도대로 반복해서 쏠 수 있게 만드는 것을 첫 번째 개선으로 삼는다.** 첫 번째 이용자는 조작법과 목표를 이해하고도 세기를 일관되게 조절하지 못해 플레이를 중단했다. 두 번째 이용자는 기본 루프와 강화를 즐겼지만 벽·누운 기물의 물리와 중량 설명에서 기대와 결과의 차이를 지적했다.

따라서 우선순위는 **입력의 정확성 → 부분 파워 조절 범위 → 실패·무승부 후 재도전 → 강화의 실제 효과 설명 → 물리 접촉 검증**이다. 충돌음과 간결한 화면은 보존하고, 파티클을 늘리거나 강화 수치를 일괄 상향하는 작업은 선행하지 않는다.

이 문서는 두 이용자의 주관적 경험을 개선 요구로 취급한다. 두 명의 의견만으로 전체 이용자의 이탈률·밸런스·플랫폼 심사 결과를 단정하지 않는다. 아래의 제안 수치는 구현 후 비교할 시험값이며 현재 적용값이 아니다.

### 적용 범위

- 우선 대상: itch.io 웹판, 노트북·데스크톱 마우스, 클래식 드래그 및 당구식 파워 드래그.
- 공통 입력·물리 변경은 공통 웹, Android, CrazyGames의 영향을 함께 확인한다. 튜토리얼·스테이지 개선은 해당 모드로 제한한다.
- 현재 로그인 이용자의 자동 매칭과 게스트 방 코드 친선전을 유지한다. 계정 저장·랭크 정산·인증 규칙을 조작성 개선과 묶어 변경하지 않는다.
- 최초 작성은 기획서 범위였으며, 후속 요청으로 로컬 게임 코드와 빌드를 적용했다. 공개 사이트 업로드와 커밋·푸시는 별도 범위다.

## 3. 현재 구현과 피드백의 차이

조사 기준은 로컬 `develop`, HEAD `2856825` 및 작업 폴더의 소스다. 마지막 확인한 itch 산출물은 `285682579741-dirty-20261110060906`이다. 작업 폴더에 미커밋 변경이 있으며, 두 이용자가 실제 플레이한 빌드·입력 모드는 제공되지 않았다. 라이브 동작을 이 문서 작성 중 다시 플레이해 재현한 것은 아니다.

## 4. 상세 변경 사양

### C01. 마지막 손 위치와 발사 요청을 일치시킨다

**변경 종류: 입력 해석. 물리 최대 위력과 승패 규칙은 유지.**

1. 현재 포인터·턴·선택 기물·취소 영역·유효 release 영역을 기존 규칙대로 먼저 검사한다.
2. 유효한 발사라면 `pointerup`의 마지막 좌표로 파워와 방향을 한 번 갱신한다. 클래식과 당구식은 각각 기존 방향 계산 방식을 사용한다.
3. 같은 최종 상태로 HUD와 발사 요청을 만든다. 실제 물리가 받는 세기는 HUD 반올림 전의 원래 값이다.
4. 이후 같은 제스처를 다시 소비하지 못하게 정리한다. `pointercancel`, 화면 밖 release, 포커스 상실, 턴 종료는 발사하지 않는다.
5. 조준 중 카메라 전환이 있으면 시작점·카메라 축을 임의로 섞지 않는다. 기존의 고정 축/당구식 현재 시점 규칙을 따른다.

**필수 재현:** 마지막 이동은 80% 지점, 버튼을 놓는 좌표는 40% 지점인 사건열을 만든다. 최종 요청은 40%여야 한다. 반대 방향, 0%, 100%·150% 경계, 취소 위 release도 검사한다. 정상 경로에서 요청·발사·턴 소비가 정확히 한 번이어야 한다.

### C02. 파워 조절을 위한 마우스 이동 범위를 선택하게 한다

**변경 종류: 입력 해석·설정 UI. 같은 파워 요청의 실제 발사 결과는 유지.**

설정에 **조작 / Controls** 항목을 추가하고 이름을 '마우스 감도' 하나로 뭉뚱그리지 않는다. 여기서 바뀌는 것은 카메라 회전 속도가 아니라 **같은 파워를 만들기 위해 당기는 거리**다.

| 선택지 | 100%까지의 거리 시험값 | 목적 |
| --- | --- | --- |
| 짧게 / Short | 180 CSS px | 기존 조작으로 돌아가는 선택 |
| 보통 / Standard | 240 CSS px | 첫 비교의 기본 후보. 부분 파워 조절 공간 확대 |
| 정밀 / Precise | 360 CSS px | 큰 화면에서 작은 힘을 조절하기 위한 후보 |

- **240px를 새 기본값으로 확정하지 않는다.** 기존 180px와 비교 검증 후 채택한다. 첫 패치에서 연속 슬라이더·비선형 곡선·별도 발사 버튼을 함께 도입하지 않는다.
- 설명: `Longer pull distance makes small power adjustments easier. Maximum shot power stays the same.`
- 설정은 로컬 기기 환경설정으로 저장한다. 계정 진행 revision·클라우드 저장 요청에 섞지 않는다. 저장 불가 시 현재 세션에만 유지한다.
- 드래그 시작 때 선택값과 유효 조작 범위를 고정한다. 드래그 중 설정·창 크기가 바뀌면 기존 제스처를 취소하고 다시 시작하게 한다. 파워가 갑자기 뛰어오르면 안 된다.
- 작은 iframe 또는 화면 가장자리에서 선택한 거리로 최대 파워에 닿지 못하면 그 프리셋을 사용할 수 없다고 표시한다. 몰래 위력을 제한하거나 뒤늦게 감도를 바꾸지 않는다. 실제 가능한 제스처 범위를 재현한 뒤 프리셋 지원 여부를 결정한다.
- 룩·퀸의 150%는 100% 기준 거리의 1.5배가 필요하다. 해당 화면에서 전체 구간에 도달할 수 있는지 별도로 검사한다. 타점에 따른 100/150% 상한은 기존 규칙을 따른다.
- Android·터치의 현재 거리 정책은 첫 묶음에서 유지한다. CSS px와 물리 픽셀·DPR을 혼동하지 않는다.

**실패 시 대안:** 정밀 프리셋이 화면 밖 release를 늘리면 기본 거리 확대를 채택하지 않는다. 다음 후보는 방향을 유지한 채 세기만 조절하는 보조 입력이며, 별도 사용자 검사 후 결정한다.

### C03. 파워 표시를 읽게 하고 궤적을 과장하지 않는다

- 기존 HUD에 **25 / 50 / 75 / 100%** 눈금을 추가한다. 허용 기물에만 150% 구간을 표시한다. 50%에서 임의 스냅·추가 힘을 주지 않는다.
- 현재 퍼센트·시위·방향 안내가 같은 파워 상태를 읽는다. 색만으로 구간을 구분하지 않는다.
- 안내: `Pull a little for a softer shot. Move back toward the piece to reduce power.`
- 조준선은 **현재 발사 방향**임을 분명하게 한다. 기존 안내가 정지 위치·충돌 후 경로의 확정 예측처럼 읽히지 않게 끝점·문구를 정리한다.
- 충돌 이후 궤적, 자동 명중 보정, 최적 파워 추천은 첫 개선에서 도입하지 않는다. 물리 예측이 불완전한데 정확한 결과처럼 표시하는 방식은 피한다.
- 향후 연습용 정지 거리 범위를 검토한다면 빈 평지·해당 기물·현재 강화 조건에서 측정한 **참고 범위**로 제한한다. 랭크 모드에는 검토 없이 적용하지 않는다.

### C04. 초반에는 파워 조절을 배우고 무승부 후에는 같은 단계에서 다시 한다

#### 파워 연습

기존 첫 샷 연습의 설명을 길게 늘리지 않는다. 강한 발사 성공 후 원하는 사람에게 **'약한 샷 연습 / Practice a softer shot'**을 제공한다. 메뉴의 튜토리얼에서도 같은 연습에 바로 들어갈 수 있게 한다.

- 같은 기물·평지 배치에서 30~50% 구간을 맞춰 보게 한다. 이 구간은 시험값이며 명중·탈락의 성공 범위와 별개다.
- 목표는 부분 세기 선택이다. 상대 장외 여부와 혼동하지 않도록 `Power control practice`를 표시한다.
- 실패하면 같은 연습 배치를 즉시 복원한다. 카드·랭크·퀘스트·재화를 주지 않고 계정 진행에 쓰지 않는다.
- 연습 종료 후 원래 메뉴·단계로 복귀한다. 진행 중인 정식 런이나 체크포인트를 덮어쓰지 않는다.

#### 1스테이지

배포 빌드와 첫 샷 연습·정식 1단계의 화면을 먼저 확인한다. 현재 3 대 3 배치를 단발 퍼즐로 오인하게 하는 문구나 즉시 실패 경로가 있으면 그 경로를 수정한다. **추정으로 생명·발사 횟수를 추가하지 않는다.**

첫 단계에서 패배하면 기본 재도전 버튼을 명확하게 보이고, 필요할 때만 짧은 파워 조절 팁을 준다. 리셋 중 중복 클릭을 막고 새 보드가 준비된 뒤 입력을 연다. 다시 하기 위해 튜토리얼과 메뉴를 여러 번 거치지 않게 한다.

#### 무승부 재경기

**룰 변경 범위는 solo 스테이지의 무승부 처리뿐이다.** 온라인 무승부 정산·패배·완주 규칙은 유지한다.

- 양쪽 기물이 모두 제거되면 `Draw — replay Stage N with your current upgrades.`를 표시한다.
- 기본 버튼: **같은 단계 다시 / Replay Stage N**. 보조 버튼: 메뉴로.
- 무승부 전 단계 시작의 배치·카드·연구·런 누적 상태를 복원한다. 다음 단계로 진행하거나 카드를 새로 뽑지 않는다.
- 무승부에서는 클리어 포인트·랭크·퀘스트·마스터리·카드 선택 보상을 지급하지 않는다. 런 정산을 반복 호출하지 않는다.
- 단계 시작 체크포인트를 보존하고, 메뉴·새로고침에서도 같은 단계 시작으로 이어진다. 기존 저장 검증 조건을 만족하는지 확인한다.
- 메뉴로 나가기·새 런 시작은 기존 확인·정산 정책을 따른다. 이를 무승부 재경기와 혼동하지 않게 구분한다.

### C05. 5스테이지 난이도는 조작 개선 이후 비교한다

동일 시작 배치, 동일 카드 조합에서 4·5·6단계를 비교한다. 무강화·힘·중량·크기 등 서로 다른 상태를 섞어서 승률만 비교하지 않는다.

1. 현재 상태에서 패배 원인을 과대 파워, 과소 파워, 자해 장외, 적 첫 턴, 거대 폰 충돌, 무승부로 기록한다.
2. C01~C03만 적용한 상태를 같은 조건으로 비교한다.
3. 조작 문제를 줄인 뒤에도 5단계에 난도 상승이 집중되면 **solo 5단계의 거대 폰 도입을 6단계로 미루는 안** 하나를 비교한다. 적 힘·중량·크기를 동시에 낮추지 않는다.
4. 5단계가 지나치게 평범해지거나 6단계로 병목만 이동하면 보류한다. 일반 대전·주간 도전·온라인의 스탯과 배치를 바꾸지 않는다.

난도 조정 전후에는 기존 클리어 기록을 삭제하지 않는다. 저장된 카드·포인트 검증도 유지한다. 새 배치나 스탯 버전을 도입할 때는 진행 중 런이 어떤 규칙을 사용하는지 결정하고 전환 안내를 작성한다.

### C06. 강화의 효과와 실제 기회비용을 설명한다

#### 카드 정보 구조

카드 한 장에 다음 정보를 이 순서로 표시한다.

1. **효과명:** 힘·중량·크기 등 바뀌는 요소.
2. **이번 선택 전후:** 현재 실제 적용값 → 선택 후 실제 적용값.
3. **사용 상황:** 왜 이 선택을 하는지 한 문장.
4. **실제 손해·상한:** 코드상 존재하는 것만 표시.
5. **적용 범위:** 이번 런, 적용 기물, 다음 단계부터 적용 여부.

기물별 원래 수치·영구 연구·카드·상한을 반영한 최종값과 카드 자체 보너스를 구분한다. 예를 들어 카드 등급이 5%에서 8%로 교체되면 '추가 +8%'나 '합계 +13%'로 표현하지 않는다.

#### 체감 확인과 비교 표시

- 기존 선택 결과에 실제 적용된 변경 요약을 짧게 보여준다. 다음 단계 준비를 불필요하게 지연시키지 않는다.
- 필요 시 별도 연습 배치에서 같은 기물·같은 파워·같은 방향의 강화 전후를 비교한다. 한 번에 한 변수만 바꾼다.
- '이동 거리 +X%' 또는 '장외 저항 +X%'는 실제 측정 없이 스탯 증가율을 옮겨 적지 않는다. 재질·충돌 조건에 따라 달라지는 결과는 상황 설명으로 쓴다.
- 유효 상한에 닿아 변화가 0인 선택은 선택지에서 제외하거나 이유를 명시한다. 실제 변화가 없는데 강화된 것처럼 연출하지 않는다.
- 일반 등급의 힘·중량 기본 효과가 5%여서 눈에 잘 안 띌 수 있다. 표시·재현 검증 후에도 구별하기 어렵다면 수치 실험을 별도로 진행하며, 첫 패치에서 전체 강화율을 일괄 상향하지 않는다.

#### 중량 설명 수정

현재의 `같은 힘에서 이동거리 감소 / Shorter travel at the same power`를 무조건적인 손해 문구로 사용하지 않는다. `turn.ts`의 충격량은 `질량 × 목표 속도`이므로, 같은 파워와 다른 배수가 같은 조건에서는 질량만 바뀌어도 목표 초기 속도는 줄지 않는다. 실제 이동거리는 접촉·회전·마찰 때문에 달라질 수 있다.

| 카드 | 영어 본문 제안 | 별도 조건 및 주의 |
| --- | --- | --- |
| 중량 | `Increases piece mass. Initial launch speed at the same power stays the same.` | 충돌 상대·접촉 조건에 따라 결과가 달라짐. 장외 저항의 고정 증가율·무조건적인 거리 감소를 쓰지 않음 |
| 힘 | `Increases launch speed at the same power.` | 멀리 가는 것은 상황별 결과. 과한 힘으로 내 말도 장외될 수 있다는 조작 팁은 실제 스탯 페널티와 구분 |
| 크기 | `Larger pieces cover more space and are easier to hit.` | 유효 크기 상한과 실제 전후 값을 표시 |
| 누운 시작 | `Your pieces start the stage lying down.` | 이동·회피 이득을 보장하지 않으며 자세에 따른 장단점은 계측 후 설명 |

한국어와 영어, 다른 지원 언어의 기존 번역·fallback을 같은 의미로 갱신한다. 이후 중량에 초기 속도 손해를 의도적으로 추가하려면 문구 수정과 별개의 밸런스 변경으로 승인·검증한다.

### C07. 짧은 설명에서 불필요한 펼침을 제거한다

- 일반 카드의 설명이 짧으면 본문에 항상 표시하고 `Show more / Details`를 제거한다.
- 예외 규칙·기물 감소·누운 시작처럼 본문을 넘는 정보가 있을 때만 펼침을 남긴다. 펼치면 본문에 없던 유용한 내용이 나와야 한다.
- 펼침 제목은 내용을 말한다. 예: `Which pawns are removed?` 또는 `How does this affect movement?`.
- 설명 펼침·키보드 탐색·스크롤이 카드 선택으로 처리되지 않게 한다. 한 번 선택은 한 번만 적용하고 로딩 실패 시 재시도가 가능해야 한다.
- 작은 창·영문·한글에서 본문이 잘리지 않아야 한다. 정보가 늘어도 카드 선택 화면 전체를 읽는 비용은 줄이는 방향으로 검토한다.

### C08. 자동 매칭과 친구 대전을 구분한다

| 이용 목적 | 안내 제목 | 동작 및 조건 |
| --- | --- | --- |
| 다른 이용자 찾기 | Find an opponent | 게임 안 로그인 → Classic 또는 Strategy → Find Match. 같은 모드에서 검색하는 다른 이용자 필요 |
| 특정 친구와 대전 | Play with a friend | 방 만들기 → 코드 공유 → 친구가 코드 입력. 게스트도 사용 가능 |

- itch.io 사이트 로그인과 게임 안 계정 연결이 다를 수 있음을 짧게 설명한다. 이미 연결된 이용자에게 다시 로그인하라고 하지 않는다.
- 게스트에게 자동 매칭을 누를 수 있는 것처럼 보여준 뒤 방 코드로만 보내지 않는다. 로그인하여 상대 찾기와 친구 방 입장을 구분한다.
- 검색 화면은 선택 모드·경과 시간·나 외의 대기자·취소를 보여준다. 0명은 오류나 가짜 AI 상대가 아니라 현재 대기자가 없다는 뜻이다.
- `No other players are searching in Classic right now. You can keep waiting or cancel and invite a friend.`처럼 실제 상태에 맞는 문구를 제공한다.
- Classic/Strategy가 서로 다른 큐라는 사실을 안내한다. 방 코드가 자동 매칭 큐의 입장 코드처럼 읽히지 않게 한다.
- 기존 11월 10일 입장·취소 검증은 참고 자료다. 두 계정의 경기 성사·완료·정산을 검증한 것으로 확대하지 않는다.

### C09. 벽 반응과 보이는 형태를 맞춘다

벽 충돌체·재질·반발·마찰과 실제 접근 각도를 먼저 검사한다. 단순히 사실적인 소리·파편을 추가해서 접촉 불일치를 덮지 않는다.

- 기준 모델: 파괴형 벽 높이 0.16, 두께 0.08 월드 단위, 한 변 8조각. 렌더와 충돌체는 같은 정의를 사용한다. 낮은 벽을 넘는 현상과 보이지 않는 가상 평면에 튕기는 결함을 구분한다.
- 파괴형은 '두 번의 새 접촉 후 파괴', 포켓 벽은 '파괴되지 않음'이라는 규칙을 첫 해당 단계에 한 문장으로 안내한다. 한 번의 연속 접촉을 프레임마다 여러 타격으로 세지 않는다. 한 번의 샷도 서로 다른 말의 접촉 등으로 여러 타격을 만들 수 있으므로 '두 샷 후 파괴'라고 쓰지 않는다.
- 기존 첫 타격의 균열 표시를 재사용한다. 영상에서 알아보기 어렵다면 균열 대비와 해당 조각의 짧은 접촉 강조만 조정하고, 파괴 전후에 메시와 바디가 함께 제거되는지 확인한다.
- 낮은 벽·높은 벽·끝단·모서리에서 기물의 실제 충돌 위치와 렌더 위치를 겹쳐 확인한다.
- 같은 입사 조건에서 같은 종류 벽이 같은 방식으로 반응해야 한다. 기물이 벽보다 충분히 높게 지나갈 때 가상의 무한 높이 장벽에 부딪히지 않는지 확인한다.
- 서로 다른 재질의 반응 차이가 의도된 것이라면 형태·재질 표현과 맞춘다. 고정된 벽이 움직이는 벽처럼 보이면 렌더를 수정한다.
- 파괴형 벽의 파괴 전후 상태, 높은 속도의 관통, 경계 seam과 측면 접촉을 별도로 검사한다.
- 원인이 충돌체 불일치라면 먼저 크기·높이·위치만 수정한다. 반발·마찰 전체 조정은 단독 비교 후 결정한다.

### C10. 누운 기물은 실제 접촉과 발사 규칙으로 설명한다

- 현재 기물은 3D 물리이며, 넘어짐이 렌더 장식에만 존재하는 구조는 아니다. 별도의 넘어짐 배율이 없다는 사실과 바닥 접촉·관성 차이가 없다는 주장은 구분한다.
- 같은 기물의 선 자세·기울어진 자세·누운 자세를 동일한 빈 보드에서 비교한다.
- 발사 속도·적용점·회전·바닥 접촉면·마찰·정착 보정의 영향을 분리한다. 단순히 '누우면 속도 50%' 같은 임의 배율을 먼저 추가하지 않는다.
- 실제 시험에서는 초기 속도 변화, 1초 후 이동·회전, 정지까지 시간과 거리를 따로 기록한다. 이 프로젝트는 `FIXED_STEP = 1/120`, `TIME_SCALE = 2`이므로 '1초'가 시뮬레이션 시간인지 실제 경과 시간인지 반드시 구분한다.
- 현재 자세에 맞는 중심 타격·표면 타격이 실제 물리 요청과 대응해야 한다. 중심 타격에 설명되지 않은 추가 회전을 넣지 않는다.
- 선 기물과 누운 기물의 차이가 작은 것이 모델상 가능한 결과인지, 회전 잠금·강제 기립·정착 시 덮어쓰기로 차이가 사라진 것인지 구분한다.
- 보정이 원인이면 해당 보정의 목적을 확인한 뒤 최소 범위로 수정한다. 무제한 굴림·턴 종료 지연·기립 실패를 새로 만들면 안 된다.
- 누운 시작 카드의 설명은 실제 적용 자세와 일치해야 한다. 단순히 낮아 보인다는 이유만으로 명중 회피나 이동 거리 이득을 보장하지 않는다.
- 실측과 블라인드 비교에서도 자세 차이가 읽히지 않으면, **solo 단계 한정의 자세별 바닥 마찰 또는 각감쇠 중 한 변수**만 시험한다. 이는 신규 룰 후보이며 확인된 결함의 단순 수리로 포장하지 않는다. 초기 발사 속도·마찰·스핀을 동시에 바꾸지 않는다. 불리함만 늘거나 누운 시작 카드의 가치가 사라지면 채택하지 않는다.

### C11. 만족스러운 충돌음과 간결한 화면을 유지한다

두 이용자는 충돌과 게임 루프의 장점을 확인했다. 배경음과 충돌음을 크게 교체하거나 화면 흔들림·입자 효과를 늘리는 작업은 보류한다.

추가 강조가 필요하다면 실제 접촉에 짧은 작은 강조 하나만 비교한다. 동작 줄이기·음소거를 존중하고 물리 시간·조준 카메라·턴 시계를 바꾸지 않는다. 잘 맞는다고 느낀 음악과 타격음의 관계를 다시 청취하며, 음악에 맞춰 충돌 시점을 지연시키지 않는다.

### 재검수 방식

가능하면 피드백을 준 두 이용자에게 같은 빌드·같은 과제를 제공한다. 추가로 처음 하는 이용자를 포함하되 인원 수만으로 통계적 효과를 주장하지 않는다.

- 질문: '50% 부근을 의도대로 반복해서 선택할 수 있었나요?', '놓았을 때 예상보다 세게 발사됐나요?', '중량 카드를 선택하면 무엇이 바뀐다고 이해했나요?'.
- 환경 기록: 빌드 번호, 브라우저, viewport, 브라우저 배율, 입력 모드, 프리셋, 단계, 카드 상태.
- 개발용 재현 로그는 로컬에서만 수집한다. 세기·방향·충돌·단계 결과만 남기고 계정 토큰·이메일·비공개 인증 정보는 포함하지 않는다.
- 기분이 좋아졌다는 답과 입력 정확도가 좋아졌다는 측정을 별도로 기록한다. 좋아진 점·나빠진 점을 모두 남긴다.

## 6. 구현 순서와 배포 경계

| 묶음 | 작업 | 다음 단계로 가는 조건 |
| --- | --- | --- |
| A 입력 정확성·문구 정합성 | C01, 기존 파워 표시값과 실제 요청 비교, 중량 문구 수정 | 재현 가능한 입력 불일치가 해소되고 취소·중복 발사 회귀 없음. 문구가 실제 모델과 일치 |
| B 정밀 조작 | C02·C03·선택형 약한 샷 연습 | 부분 파워 과제 통과, 작은 iframe·150% 구간 도달 검증 |
| C 진행·설명 | 무승부 재경기, C06·C07·C08 | 저장·보상 불변식, 설명 이해, 실제 온라인 경로 검사 |
| D 물리·난이도 | C09·C10 재현 후 최소 수정, C05 단일 요인 실험 | 실제 접촉·자세 오류와 체감 차이를 구분하고 네트워크·턴 정착 회귀 없음 |
| E 추가 연출 | C11의 절제된 접촉 강조 후보 | A~D 결과가 안정적이고 기존 스타일·음향을 해치지 않을 때만 진행 |

입력 프리셋은 물리 최대 위력·보상을 바꾸지 않으므로 다른 물리 밸런스 실험과 구분해 배포할 수 있다. 벽·질량·마찰·회전 같은 공통 물리 변경은 양쪽 클라이언트가 같은 규칙을 쓰는지 확인하기 전 온라인에 섞어 적용하지 않는다. 필요하면 solo 한정 시험을 먼저 하고 공통 적용을 보류한다.

기존 배포물과 설정 초기값은 비교·복구용으로 보관한다. 입력 설정은 기본값 복구가 가능해야 하며, 저장 형식을 바꾸면 구버전 체크포인트 처리 정책을 먼저 작성한다. 운영 계정 데이터를 삭제하거나 충돌 검사를 우회해 문제를 해결하지 않는다.

## 7. 이번에 하지 않을 작업

- 결과를 보장하는 전체 충돌 궤적 예측, 자동 명중·자동 세기 추천.
- 모든 강화 수치 일괄 상향, 공통 물리 엔진 교체, 사실적 물리라는 이유만의 대규모 리팩터링.
- 가짜 대기 인원·가짜 매칭 상대, AI를 사람 상대처럼 표시하는 기능.
- 큰 화면 흔들림·과도한 파티클·새 배경음으로 조작 문제를 보완하는 작업.
- CrazyGames 입점·잼 수상·이용자 유지율 상승을 보장하는 표현.
