# 조준 안내 설계 (2026-07-25 확정)

슬라이스 5 이후 조준 안내를 여섯 번 갈아엎은 결과와 그 근거를 남긴다.
같은 실패를 반복하지 않기 위한 문서라, **폐기한 시도와 그 이유**를 확정안보다 먼저 적는다.

## 1. 요구사항

개발자가 명시한 제약이다.

1. **어디에 떨어지는지 알려주면 안 된다.** 대략적인 방향만 보여준다.
   - "궤적을 그렇게 길게 하면 정확히 어디로 가는지 다 보이잖아. 그러면 안돼."
2. 세기는 안내선의 **형상을 바꾸면 안 된다.** 색과 활줄로만 표현한다.
3. 시점을 돌려도 **힘을 주는 위치는 말의 시각적 중심에 고정**이다. 방향만 시점을 따라간다.
4. 넘어진 말에서도 안내가 판 밑으로 들어가지 않고 제대로 보여야 한다.
5. 거리와 위치를 **실제로 잴 수 있어야** 한다.

2번을 지키기 위해 안내 곡선은 실제 발사 속도가 아니라 고정 명목 속도
`NOMINAL_GUIDE_SPEED = 3.5`와 고정 호 길이 `GUIDE_ARC_LENGTH = 2.2`만 사용한다.
세기 0 / 0.5 / 1에서 생성되는 geometry가 바이트 단위로 동일함을 해시로 검증했다.

## 2. 폐기한 시도

### 2-1. 직선 화살표 (ArrowHelper)

원근이 없어 어느 방향으로 가는지 읽히지 않았다.
넘어진 말에서는 화살표가 판 아래로 들어가 아예 안 보이는 문제도 있었다.

### 2-2. 실제 궤적 전체

요구사항 1 위반. 착지점이 그대로 노출돼 개발자가 거부했다.

### 2-3. 공중에 원뿔 여섯 개 나열

원뿔이 시선 방향과 겹쳐 **밑면 원만 보인다.**
외곽선 추가, 거리별 명암 테이퍼, 크기 테이퍼, 간격 2배, 호 길이 2배까지 전부 적용했지만
구조적으로 개선되지 않았다. 높은 피치에서는 곡선 대부분이 판 아래로 내려가
화면에 원 두세 개만 남았다.

## 3. 핵심 발견 — 3차원 지시선으로는 고도를 표현할 수 없다

당구식에서 카메라 피치와 조준 고도는 잠겨 있다.

```
u = (pitch - 3) / 82
고도 = 60 - 120u
```

발사 방향을 화면에 투영했을 때의 세로 성분은 `sin(고도 + 피치)`이다.
피치 3°~85° 전 구간에서 이 값을 계산하면 다음과 같다.

| 카메라 피치 | 조준 고도 | 화면 세로 성분 | 화면상 방향 |
|---:|---:|---:|---|
| 3° | +60° | 0.891 | 위 |
| 19.4° | +36° | 0.823 | 위 |
| 44° | 0° | 0.695 | 위 |
| 60.4° | −24° | 0.593 | 위 |
| 76.8° | −48° | 0.482 | 위 |

**어떤 고도로 조준해도 항상 양수, 즉 화면상 위쪽을 가리킨다.**
개발자의 "항상 화살표는 위를 가리키는 걸로 보여"라는 지적이 문자 그대로 맞았고,
두께·색·길이·개수 어떤 조정으로도 원리적으로 고칠 수 없다.

→ **고도는 3D 장면이 아니라 화면 좌표 계기로만 표시한다.**

## 4. 확정 구성

### 4-1. 바닥 진행 띠 — 주 표시

보드 상면(`y = 0.003`)에 깔린 사다리꼴 띠다. 시선과 비스듬히 만나기 때문에
원근이 살아나고, 무엇보다 **체스판 칸과 겹쳐서 칸 수로 거리를 읽을 수 있다.**

- 길이: **고정 1.6** (약 3칸). 고도·세기 어디에도 반응하지 않는다.
- 시작점: 선택한 말의 월드 bounding sphere 표면. 말 크기에 따라 자동으로 밀린다.
- 폭: 0.3 → 0.16 테이퍼. 알파 0.45로 칸 무늬가 비친다.
- 화살표 5개 + 거의 검은색(`0x121212`) 외곽선 1.18배.
  밝은 칸과 어두운 칸 모두에서 실루엣이 분리된다.

길이를 곡선의 수평 길이에 맞췄던 초기안은 폐기했다. 고도에 따라 간격이
0.098까지 좁아져 화살표가 겹쳤다. 고정 길이로 바꾸면 간격이 항상 0.2667이고
외곽선을 포함한 최소 여유가 0.058이라 **어떤 고도에서도 겹치지 않는다.**

### 4-2. 공중 고도 띠 — 보조 표시

곡선을 따라가되 폭 방향을 매 프레임 카메라 쪽으로 다시 잡는 빌보드 리본이다.
폭 0.08, 불투명도 0.6.

**말을 벗어난 지점부터 보드 상면에 닿는 순간까지만** 그린다.
자르지 않으면 고도 0°에서도 끝점이 시작점보다 1.21 아래라 대부분이 판 밑에 그려진다.
자를 구간이 없으면(가파른 하향 조준) 숨긴다.

수직 연결선은 제거했다. 상면에서 자르고 나면 항상 길이가 0이 된다.

### 4-3. 고도 계기

판을 옆에서 본 SVG 그림이다. 바늘이 발사 각도만큼 회전하고 아래에 `고도 ±N°`가 뜬다.
화면 좌표라 원근 왜곡이 없다. 왼쪽 아래에 두고 **당구식에서만** 표시한다.
클래식은 항상 수평이라 계기가 의미 없다.

오른쪽 아래는 기존 조준 수치판이 쓰므로 자리를 피했다.

### 4-4. 렌더 순서

| 요소 | 주 패스 | 보조 패스 |
|---|---|---|
| 바닥 띠·화살표·공중 띠 | depthTest 켬, order 20 | depthTest 끔, opacity 0.35, order 19 |

선택 고리 10 < 안내 19/20 < 빨간 점 30.

## 5. 두 표시의 보완 관계

낮은 피치에서는 보드가 눈높이에 가까워 바닥 띠가 얇아지지만,
그 구간이 공중 호가 가장 길고 높게 서는 구간이다. 높은 피치에서는 정반대로
바닥 띠가 완전히 펼쳐지고 공중 호는 짧아진다.
그래서 **둘 다 필요하다.** 하나만으로는 전 구간을 못 덮는다.

## 6. 검증

- 세기 0 / 0.5 / 1에서 바닥 띠 화살표 위치가 픽셀 단위로 동일함을 화면으로 확인.
- 고도 +60 / +16 / 0 / −60에서 계기 바늘이 각도대로 기울고,
  −60에서 공중 호가 정상적으로 숨는 것을 확인.
- 화살표 간격 0.2667 / 외곽선 최소 여유 0.0582 계산으로 겹침 없음 확인.
- 발사·턴 전환·클래식 모드 계기 숨김까지 브라우저에서 직접 조작해 확인.
