# PVE 진행 설계 (2026-07-26 시작)

기획자 기획안(2026-07-26 전달)과 개발자 확정 답변을 단일 기준으로 정리한다.
이 트랙의 슬라이스는 W1~W5로 번호를 붙인다.

## 1. 기획 원문 요약

**스테이지 대전(컴퓨터 상대)** — 스테이지 번호의 배수 규칙으로 컴퓨터 말이 강해진다.

| 규칙 | 효과 |
|---|---|
| 짝수 스테이지 (2,4,6…) | 중량 상승 |
| 홀수 스테이지 (3,5,7…) | 가하는 힘 상승 |
| 3의 배수 (3,6,9…) | 크기 소폭 상승 |
| 5의 배수 (5,10…) | 폰 크기 상승 (5단계: 룩 크기 / 10단계: 킹 크기) |

**일회성 업그레이드** — 판 승리 시 업그레이드 카드 3장 등장, 1장 선택. 그 판(런) 동안만 유효.

- a. 크기 소폭 상승
- b. 중량 상승
- c. 가하는 힘 상승
- d. 폰이 킹 사이즈만큼 커짐, 폰 4개 소멸
- e. 모든 체스 말이 누워져서 시작

**영구 업그레이드** — 게임 메인 화면에서 포인트로 구매, 테크트리 방식.

- a. 말 종류별 힘 증가 (0.01)
- b. 말 종류별 중량 증가 (0.01)

## 2. 확정 답변 (개발자, 2026-07-26)

1. 스테이지 버프의 대상은 **컴퓨터 쪽 말**이다.
2. 배수 규칙이 겹치면 **둘 다 적용**하고, 버프는 **스테이지마다 누적**된다.
   (2단계에 중량이 올랐으면 3단계는 그 중량 + 힘 상승)
   밸런스가 너무 빨리 강해지는 우려가 있으나, 한 번의 증가폭을 상수로 두고 나중에 튜닝한다.
3. 카드 e "모든 체스 말이 누워져서 시작" = **플레이어 말만** 눕는다.
4. 카드 d = 폰 8개 중 **4개가 소멸하고 남은 4개가 킹 크기**가 된다.
5. 영구 강화의 0.01 단위 = **손맛 조절판(T)에서 조절하는 값과 같은 단위**. 정확한 배율은 구현 때 튜닝.
6. 스테이지 클리어 포인트 = **일단 100**. 나중에 조절.

## 3. 진행 중 가정 (개발자 부재 중 설계자가 정한 것 — 복귀 후 확인 대상)

- **동시 전멸**: 마지막 발사로 양쪽 말이 함께 전멸하면 **방금 친 쪽 승리**. (공격 목적을 달성한 쪽 우선)
- **스테이지 버프 증가폭 초기값** (전부 config 상수, 조절판과 같은 철학으로 튜닝 전제):
  - 중량: 짝수 스테이지마다 원래 질량의 +10%p 누적 (밑동 추와 같은 방식의 추가 질량)
  - 힘: 홀수 스테이지마다 컴퓨터 발사 속도 +5%p 누적
  - 크기: 3의 배수마다 +3%p 누적 (렌더+콜라이더 동시 스케일)
  - 폰 크기: 5단계에 룩 높이, 10단계에 킹 높이로 고정 치환 (누적 아님, 단계 도달 시 교체)
- **AI 1차 구현은 단순 휴리스틱**: 자기 말 중 하나를 골라 가장 가까운 플레이어 말을 향해,
  거리 비례 세기(+소폭 무작위성 대신 결정적 변형)로 발사. 정밀 시뮬레이션 AI(Rapier 스냅샷 탐색)는 후속 고도화.
- **영구 강화 저장**: 브라우저 localStorage. 키 접두사 `chessAlkkagi.meta.`
- **중앙 전체 크기 노드 적용 진영 (07-28, ROUND 54 해석)**: 기획서 10쪽은 "전체 말 크기"가 어느
  진영에 적용되는지 명시하지 않는다. 영구 성장 트리의 문맥과 기존 W5의 "영구 강화는 흰 말에만" 규칙에 따라
  **플레이어가 소유한 모든 백 말 종류에만 +3%**를 적용한다고 가정한다. 기획자가 한 줄로 확인하거나 뒤집을 수 있는
  미확정 해석이다.
- **모드 구분**: 기존 2인 핫시트는 남긴다. 메인 화면에서 "2인 대전 / 스테이지 대전" 선택.
  (W5 전까지는 화면 위 임시 토글 버튼으로 모드를 바꾼다 — W5에서 메인 화면으로 이동)
- ~~**PVE 카메라**: 스테이지 대전에서는 카메라를 흑 쪽으로 돌리지 않는다~~ → **폐기(07-26 개발자 결정)**:
  스테이지 대전도 2인 대전과 **동일한 턴 카메라 회전**을 쓴다. AI는 회전 완료 후 ready 진입 0.8초 뒤
  발사하므로 타이밍 로직은 그대로다.
- **W3 추가 가정 (07-26)**:
  - **패배 시 런 종료** — 스테이지 1부터 다시 시작한다. (일회성 강화가 "판이 끝나도 소멸되지 않는" 영구 강화와
    구분되는 구조상, 연속 스테이지 진행 = 런이고 패배가 런의 끝이다)
  - 승리 시 결과 화면 버튼은 "다음 스테이지", 패배 시 "다시 시작"(스테이지 1).
  - **힘 버프는 세기 클램프가 아니라 목표 발사 속도의 배수**로 적용한다. (세기 1.0에서 포화되면 버프가 무의미)
  - 폰 크기 티어(5단계 룩/10단계 킹)는 높이 비율 배수로 구현하고, 일반 크기 버프와 곱으로 결합한다.
  - HUD에 스테이지 번호를 표시한다.
  - **폰 지그재그 배치 (07-26, R30 실측으로 확정)**: 킹 크기 폰 8개는 한 줄에 물리적으로 들어가지 않는다
    (받침 지름 0.66 × 8 > 줄 폭 — 스테이지 12 사전 정착 실측에서 끝 폰 a7·h7이 2.17 밀려나며 수면 실패).
    확대된 폰의 받침 지름이 "칸 간격 − 0.02"를 넘으면 **짝수 번째 폰을 한 칸 앞(보드 중앙 쪽)으로 옮겨
    지그재그 2열**로 배치한다. 대각 간격 0.758이 확보된다. 룩 크기 티어는 한 줄에 들어가므로 그대로.
  - **말 크기 상한 STAGE_MAX_PIECE_SCALE = 2.2**: 스테이지가 아주 높아지면(약 30+) 지그재그로도 안 들어가므로
    총 배율을 상한에서 자른다. 중량·힘 버프는 계속 누적되므로 난이도는 계속 오른다.
- **W4 추가 가정 (07-26)** — 일회성 카드 상세:
  - 스테이지 승리 화면에서 카드 3장을 보여주고 1장을 고르면 곧바로 다음 스테이지로 진입한다(별도 버튼 없음).
  - 효과는 **플레이어(백) 말에만**, **런 범위**(패배·모드 전환 시 소멸). 매 보드 리셋 때 재적용.
  - a 크기(+0.03 배율)·b 중량(+0.10 질량)·c 힘(+0.05 발사 속도 배수)은 **중복 선택 시 가산 누적**.
    c는 AI 힘 버프와 같은 방식(세기 클램프가 아니라 목표 발사 속도 배수)으로 플레이어 발사에 적용.
  - d 거대 폰(1회성, 뽑으면 풀에서 제거): **a·c·e·g 파일 폰 4개 소멸, 남은 b·d·f·h 폰이 킹 크기**.
    남은 폰 간격이 2칸(1.072)이라 킹 크기 받침(0.66)이 한 줄에 들어간다 — 지그재그 불필요.
  - e 포복 개시(1회성, 뽑으면 풀에서 제거): **백 말이 전부 누운 채 시작**.
    배치 규칙(기하 실측 근거): 뒷줄(1랭크)은 머리를 보드 중앙 쪽(북)으로 눕히고 받침을 남쪽 보드 경계에
    붙인다(킹 길이 1.0이 랭크2 폰과 0.05 여유로 안 겹침). 폰(2랭크)은 제자리에서 동쪽으로 눕힌다
    (폰 길이 0.52 < 칸 0.536이라 제자리 성립). 사전 정착 32/32 필수.
  - 카드 3장 추첨은 결정적: (스테이지, 지금까지 뽑은 카드 수) 정수 해시로 남은 풀에서 서로 다른 3장.
    풀이 3장 미만이면 있는 만큼만 보여준다. Math.random 금지.
  - **백 크기 카드 상한 PLAYER_MAX_SIZE_SCALE = 1.20 (07-26, R31 스트레스 실측으로 확정)**:
    크기 카드를 무한 중첩하면 백 뒷줄 8개가 한 줄에 물리적으로 안 들어간다(상한 2.2에서 필요 폭 6.4 > 판 4.29,
    구석 말 압출 낙하 실측). 뒷줄 최악 인접쌍(퀸+킹 받침 합 0.429×s ≤ 0.516)에서 s=1.20이 한계.
    거대 폰(폰 티어)만 예외적으로 2.2 상한 사용(2칸 간격이라 성립). 크기 스택이 상한에 닿으면 크기 카드를 풀에서 제거.
- **W5 추가 가정 (07-26)** — 포인트·영구 강화·메인 화면:
  - **메인 화면**: 접속 시 메뉴 화면에서 시작 — "2인 대전" / "스테이지 대전" 버튼 + 보유 포인트 + 영구 강화 패널.
    인게임 우상단의 임시 모드 토글은 제거하고 "메뉴로" 버튼으로 대체(누르면 진행 중 런 포기 확인 후 메뉴 복귀).
  - **포인트**: 스테이지 클리어 시 +100 (개발자 확정). 즉시 저장.
  - **영구 강화 노드**: 말 종류 6 × (힘 / 중량) 2트랙 = 12노드. 레벨당 효과 +0.01
    (힘 = 그 종류 말을 쏠 때 발사 속도 배수 +0.01 / 중량 = hull 질량 비율 +0.01), 최대 레벨 10.
  - **비용**: 기획 미확정 → 레벨 N→N+1 비용 = 100 × (N+1) (선형 증가). 상수화해 나중에 조절.
  - **테크트리 구조**: 기획서에 노드 간 관계 상세가 없어 **1단계 전 노드 개방(평면형)**으로 시작.
    관계형 잠금은 기획자 상세가 나오면 후속. (창작하지 않는다)
  - **저장**: localStorage `chessAlkkagi.meta.points` / `chessAlkkagi.meta.upgrades`. 저장 실패(사생활 모드 등)는
    경고만 하고 세션 메모리로 동작.
  - 영구 강화는 흰 말에만, 카드·스테이지 효과와 같은 합성 경로로 결합.
- **AI 1차 규칙(결정적)**: 준비 상태 진입 후 짧은 지연(약 0.8초) 뒤,
  자기 말 중 플레이어 말과 가장 가까운 말을 골라 그 플레이어 말을 향해 수평 발사.
  세기 = 거리 비례식(최소~최대 클램프). 매 턴 같은 상황이면 같은 수가 나오도록
  (스테이지, 턴 번호) 기반의 결정적 각도 변형(±5° 이내)만 준다. Math.random 금지.

## 4. 슬라이스 분해

| 슬라이스 | 내용 | 선행 |
|---|---|---|
| **W1** | 승패 판정 + 결과 화면 + 다시 시작 — ✅ 완료·게이트2 통과(07-26) | 없음 |
| **W2** | 컴퓨터 상대(AI) 턴 + 스테이지 대전 모드 진입 — ✅ 완료·게이트2 통과(07-26) | W1 |
| **W3** | 스테이지 진행(1→2→…) + 누적 버프(중량/힘/크기/폰 크기) — ✅ 완료·게이트2 통과(07-26) | W2 |
| **W4** | 판 승리 시 일회성 카드 3장 선택 (a~e) — ✅ 완료·게이트2 통과(07-26) | W3 |
| **W5** | 포인트 + 영구 강화 테크트리 + 메인 화면 — ✅ 완료·게이트2 통과(07-26) | W4 |

**트랙 상태: 기획안 전 항목 구현 완료 (2026-07-26).** 커밋은 개발자 복귀 후.

승리 = 상대 말 전부 판 밖 낙하 (기존 확정 룰). 넘어진 말은 산 말이다.

## 5. 검증 방침

- 각 슬라이스는 tsc + 빌드 + (물리 관련이면) 하네스 재검증.
- UI 흐름은 설계 Claude가 브라우저 자동화로 게이트2 확인.
- 커밋은 하지 않고 작업 트리에 쌓는다. 개발자 복귀 시 슬라이스별 커밋 제안 일괄 전달.
