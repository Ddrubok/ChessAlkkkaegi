## 1. 시작 흔들림 제거 (요구 3)

**원인 실측**: 말을 판에 정확히 맞닿게 스폰 → 솔버가 초기 접촉을 푸는 과정이 그대로 보인다.
32개가 약 2.1 시뮬레이션 초(실제 0.67초) 미세 진동(최대 1.5°), 그 뒤 **1개가 4.25 시뮬레이션 초(실제 1.34초)까지 혼자 떤다.**

**해결: pre-settle** — 첫 렌더 전에 물리를 미리 돌려 재운다.
- 실행 시점: **물리 런타임 생성 직후, 턴 런타임 생성과 RAF 시작 전.**
- 전원 sleep까지 `world.step()` 반복, 상한 `PRE_SETTLE_MAX_STEPS = 1200`(10 시뮬레이션 초, 실측 최악 4.25초의 2.35배).
- 성공 후 **렌더 메시를 정착 자세로 동기화**하고, 게임 계측(턴 phase·physics step 번호·settle 타이머·accumulator)은 **0에서 시작**한다.
  pre-settle 시간을 플레이 시간으로 세지 않는다.
- 소요 스텝 수와 **CPU 소요 ms**를 로그로 남긴다(저사양 기기에서 로딩을 얼마나 막는지 확인용).
- 상한에 도달했는데 32/32 sleep이 아니면 **경고 후 진행이 아니라 명시적 로딩 실패 상태로 표시**한다.
- 물리를 속이는 게 아니다. 여전히 awake로 스폰해 실제로 정착시키고, 그 과정을 보여주지 않을 뿐이다.

## 2. 조작 모델 2종 — 단일 상태 기계 + 전략 (요구 4)

**두 개의 독립 입력 경로를 만들지 않는다** (게이트1 지적 7). 슬라이스 2의 포인터 상태 기계에 이미
상대 말 관통 금지·pointer capture·멀티터치 무시·캔버스 밖 release·blur·visibility·제거된 말 정리가 들어 있고,
경로를 둘로 쪼개면 모든 버그를 두 번 고쳐야 한다.

**공유(절대 분기 금지)**: 선택, pointer capture, 취소, 발사 큐, 말 제거, 턴 잠금.

**모드별 전략 인터페이스만 교체**:
- `cameraPolicy` — 공전 중심·피치 범위·거리 범위·잠금 규칙
- `computeLaunchDirection()`
- `computeApplicationPoint()`
- `onAimBegin() / onAimCancel()`
- `usesHitPoint: boolean` — 타점·고도각 UI 노출 여부

| | **클래식**(슬라이스 2) | **당구식**(신규, 기본값) |
|---|---|---|
| 방향 | 화면 드래그의 반대 방향 | **카메라 수평 방위** |
| 세기 | 캔버스 드래그 거리 | **화면 세기 바**(캔버스 아님, §3) |
| 상하각 | 고정 | 자유 3°~85° |
| 공전 중심 | 판 중앙 | 선택한 말 |
| 최소 거리 | 판 전체가 보이는 거리 | 0.8 |
| 타점 | 고정(높이 25%, 수평) | 자유(높이·고도각·좌우) |

**전환 규칙**: 우상단 토글, `localStorage` 저장, 게임 중 전환 가능.
전환 시 조준 취소만으로 부족하다 — **카메라 target·polar angle·min/max distance·거리를 대상 모드의 계약으로 복원**하고,
복원이 끝날 때까지 새 조준을 잠근다.

## 3. 당구식 시야 (요구 1)

- **공전 중심**: 선택한 말의 **현재 월드 AABB 중심**(body origin 아님 — 원점을 쓰면 낮은 피치에서 카메라가 판·말 내부로 들어간다).
  선택 시 0.25초 보간, 해제 시 판 중앙으로 복귀.
- **피치** `CAM_PITCH_MIN` 3° ~ `CAM_PITCH_MAX` 85°.
- **거리** `CAM_MIN_DISTANCE` 0.8 ~ 판 전체가 보이는 거리(미선택 시에는 슬라이스 2의 대각선 최악 방위 거리를 최소로 유지).
- **수평 방위는 `controls.getAzimuthalAngle()`(또는 target→camera의 수평 반대 방향)로 구한다.**
  `camera.getWorldDirection()` 투영은 85°에서 수평 성분이 0.0872까지 줄어 오차를 약 11.5배 증폭한다.
  방위가 유효하지 않으면 **마지막 유효 방위로 폴백**한다.
- **캔버스는 카메라 조작 전용**(지적 2). 거리 0.8에서는 선택한 말이 화면을 크게 덮어 공전할 빈 영역이 부족해지고,
  탭 선택과 세기 드래그가 같은 `pointerdown`이라 문턱 규칙이 필요해진다. → **세기는 화면 세기 바로 분리**한다.
  캔버스 탭 = 말 선택, 캔버스 드래그 = 카메라. 세기 바 드래그 = 세기 + 놓으면 발사.

## 4. 타점 — 3파라미터 (요구 2)

전부 **숫자로 표시**한다.

| 파라미터 | 범위 | 기본 | 의미 |
|---|---|---|---|
| `hitHeight` | 0~100% | 25% | 현재 월드 AABB 높이 기준 타격 높이 |
| `cueElevation` | −60°~+60° | 0° | 임펄스 상하 각도. **양수 = 아래에서 위로 쳐올림** |
| `hitLateral` | −100%~+100% | 0% | 좌우 타점(반폭 기준). 좌우 회전·휘어짐을 만든다 |

**좌우 타점을 추가하는 이유** (지적 3): 높이와 고도각만으로는 임펄스·적용점이 무게중심을 지나는 **수직 평면 안에만** 있어
좌우 회전이 원리적으로 불가능하다. 당구의 진짜 masse(수평으로 휘는 궤적)는 이 모델로 만들 수 없다.
→ v1의 "맛세이" 표현은 **"위에서 아래로 찍기(pitch)"** 로 정정하고, 좌우 휘어짐은 `hitLateral`로 제공한다.

**토크가 상쇄되는 구간을 UI에 드러낸다** (지적 3): 초기 토크는
`τ = −w·J·sin(e) − (yHit − COMy)·J·cos(e)` 이고, Pawn(반폭 0.1531, COM y 0.2031) 기준
**타점 0%는 +53°, 20%는 +33°, 25%는 +25.5°에서 두 항이 상쇄되어 그 이상에서는 회전이 반대로 뒤집힌다.**
"낮게+위로"가 단조롭게 강해지지 않으므로, **계산된 초기 Δv와 Δω(또는 회전 방향 화살표)를 조준 중에 표시**한다.

**적용**
- 수평 방위 `d`, 좌우 단위벡터 `s = d × up`.
- 임펄스 방향 = `normalize(d·cos(e) + up·sin(e))`.
- 적용점 = `(com.x, aabbMinY + hitHeight × aabbHeight, com.z)` 에서 `−d` 방향으로 반폭만큼,
  `s` 방향으로 `hitLateral × 반폭`만큼 이동.
- 크기 = `mass × normalizedPower × MAX_LAUNCH_SPEED`.

**기대 동작 — 실측으로 교정** (지적 4). 294개 조합 실험 결과:
- **인접한(한 칸 간격) 앞말을 넘어 뒷말만 맞히는 조합은 0개였다.** v1의 기대는 과장이었다.
- **성립하는 조건**: 앞말이 **두 칸** 떨어지고 뒷말이 그 다음 칸일 때,
  `hitHeight 0~25%` + `elevation +60°` + `power 75%` → 앞말 미접촉, 뒷말 명중, 착지. 최고 높이 1.47~1.79.
- 높은 타점 + −60° + 낮은 power는 거의 전진하지 않고 제자리 회전만 한다(이동 0.0007, 최대 기울기 9.25°). 그런 조합 56개.
- 타점 20% + 45° + 최대 power, 타점 80% + −30° + 75% 이상은 **판 밖으로 나간다**(위험·보상).

→ 문서와 UI 모두 "**power와 배치에 따라 결과가 완전히 갈린다**"를 전제로 한다. 넘기기는 두 칸 이상 간격에서 가능한 기술이다.

**CCD** (지적 5): API 이름은 생성 시 `RigidBodyDesc.setCcdEnabled(true)`, **기존 바디는 `RigidBody.enableCcd(true)`**.
실측상 속도 11·25에서는 CCD 없이도 말-말 충돌 누락이 없었고, 아래로 속도 25에서 보드 관통 0.0506 후 복구,
속도 50에서 관통 0.2533(CCD 사용 시 1.1e-5).
→ **발사되는 바디에만 켜고 정착 후 끈다.** 항상 32개 전부 켜지 않는다.

## 5. 손맛 실시간 조절판 (요구 5)

접이식 패널(`T` 키 또는 `?tune=1`). **모든 항목 = 슬라이더 + 현재 값 숫자 + 숫자 직접 입력.**

| 항목 | 범위 | 기본 | 적용 API (0.19.3 확인 완료) |
|---|---|---|---|
| 시간 배속 | 0.5 ~ 4.0 | 3.162 | 루프 설정 |
| 최대 세기 | 2 ~ 25 | 11 | 발사 설정 |
| 마찰 | 0.05 ~ 1.5 | 0.4 | 말·보드 `collider.setFriction()` |
| 반발 | 0 ~ 0.6 | 0.1 | 말·보드 `collider.setRestitution()` |
| 선형 감쇠 | 0 ~ 4 | 2.0 | `body.setLinearDamping()` |
| 회전 감쇠 | 0 ~ 8 | 2.0 | `body.setAngularDamping()` |
| 밑동 추 배수 | 0 ~ 3 | 0 | `body.setAdditionalMassProperties(...)` |
| 타점 기본값 3종 | §4 범위 | §4 기본 | 조준 설정 |

전부 **바디·콜라이더 재생성 없이** 즉시 반영된다.

**밑동 추 정확한 사용법** (지적 8): `setAdditionalMassProperties(추가질량, 로컬COM, 주관성모멘트, 관성프레임, wakeUp)`.
점 질량이므로 **주관성 모멘트 `(0,0,0)`, 프레임 identity, COM은 말 로컬 좌표**로 준다.
배수 계산은 현재 총질량이 아니라 **저장해 둔 원래 hull 질량**을 쓴다(누적 시 질량이 복리로 커진다).
값은 **호출 직후가 아니라 다음 step에 반영**된다. 실측: Pawn에 ×1.5 적용 시 질량 0.027216→0.068040, COM y 0.203070→0.099961.

**두 가지 잘못된 가정 정정** (지적 9):
- **물리값 변경은 잠든 말을 깨우지 않는다.** v1의 "감쇠를 낮추면 잠든 수가 즉시 줄어든다"는 성립하지 않는다.
  → 패널에 **"값 적용 후 전체 깨우기"** 버튼을 둔다(기존 `W` 키와 같은 동작).
- **TIME_SCALE 4.0은 스텝 예산이 부족하다.** 30fps에서 정확히 16스텝, 24fps에서 20스텝이 필요해
  현재 `MAX_STEPS_PER_FRAME = 16`으로는 반드시 넘친다. → **`MAX_STEPS_PER_FRAME = 24`로 올린다**(24fps·배속 4.0에서 여유 4).

**초기화** 버튼과 **현재 값 JSON 복사** 버튼(개발자가 마음에 든 값을 그대로 전달할 수 있게).

**참고 실측(최대 세기 폰, 마찰 0.4)**: 선감쇠 2.0 → 6.60칸·0.94초·전원잠듦 6.53초 / 1.0 → 11.26칸·1.33초·3.99초 /
0.5 → 15.87칸·1.75초·미달성 / 0.2 → 57.84칸·미정지·미달성.
**감쇠를 낮추면 넘어진 말이 구르며 마찰이 거의 안 먹는다.** 회전 감쇠를 따로 올려도 넘어짐 자체는 못 막는다.

## 6. 구현 순서 (지적 11 — 핵심을 먼저 개발자에게)

1. **pre-settle**
2. **단일 상태 기계 + 전략 인터페이스 + 모드 토글 + 자유 카메라**
3. **숫자 입력 슬라이더 3종(높이·고도각·좌우) + 실제 임펄스 + 초기 Δv/Δω 표시 + 세기 바**
4. **조절판 8항목 + 깨우기 버튼 + 초기화**
5. — 여기서 개발자 플레이 확인 —
6. 이후: 말 실루엣 위젯, 3D 큐 선, JSON 복사

**1~4까지가 이번 위임 범위.** 6번은 개발자 확인 후 별도 라운드.
범용 설정 프레임워크나 이벤트 버스는 만들지 않는다.

## 7. 파일 구조

기존 10모듈 + `tuning.ts`(조절판), `aimparams.ts`(타점 3종·세기 바·Δv/Δω 계산).
`input.ts`는 **단일 상태 기계 + 전략 주입**으로 개편. `config.ts`의 §5 항목은 **런타임 변경 가능한 설정 객체**로 이동
(현재 `const`는 기본값 정의로 남긴다).

## 8. 수락 기준 (게이트2 — 시험 조건까지 고정, 지적 10)

**흔들림**
- [ ] 첫 렌더 시점 32/32 sleep, pre-settle 스텝 수와 CPU ms 로그
- [ ] 로드 후 무입력 5초간 최대 기울기 변화 ≤ 0.01°
- [ ] 상한 도달 시 명시적 실패 표시(조용한 진행 금지)

**카메라**
- [ ] 피치 3°/85°, 거리 0.8에서 **6종 × 직립·누운 상태** 각각: 방향 벡터 유한, 카메라가 메시 내부·near plane에 들어가지 않음
- [ ] 미선택 시 모든 방위에서 판 전체가 화면 안(슬라이스 2 기준 유지)
- [ ] 캔버스 드래그는 카메라만 움직이고 발사되지 않음

**타점**
- [ ] 높이·고도각·좌우가 숫자로 표시되고 슬라이더로 바뀜
- [ ] 조준 중 **계산된 초기 Δv와 Δω(또는 회전 방향)** 가 표시됨
- [ ] **넘기기 기준 시험**: Pawn, 앞말 2칸, 뒷말 3칸, `높이 0~25% + 60° + power 75%`
      → 앞말 충돌 0회, 뒷말 충돌 ≥1회, 최고 높이 기록, 판 안 착지 후 정지
- [ ] **찍기 기준 시험**: Pawn, `높이 80% + −60° + power 50%` → 최대 기울기·전진 거리·판 이탈 여부 수치화
- [ ] **CCD 시험**: 동일 스냅샷 on/off, 최대 속도 25에서 말 충돌 이벤트 수와 보드 최소 관통,
      physics step CPU 시간 평균·p95 비교(FPS 아님)
