## 0. 개발자 결정 — 타격 지점 선택 기능 취소

> "이전에 말의 중심점이 아니고, 옆이나 아래, 위를 쳐서 말을 날리는 게 어떠냐고 했었지? 그 아이디어 취소할게.
> 빨간 점은 wasd로 시야를 바꾼다고 위치가 바뀌면 안 될 거 같아. 실제랑 비슷한 느낌을 최대한 내려고 하면 게임이 조잡해질 거 같아.
> 빨간 점의 위치는 말의 중심에 위치하도록. 물론 힘을 가하는 **방향**은 시점에 따라서 변하긴 할꺼야.
> 하지만 힘을 주는 **위치**는 말의 중심에서만."

**취소된 것은 "어느 부위를 칠지 고르는 것"이고, "방향이 시점을 따르는 것"은 유지된다.**

이 판단은 게이트2 결과로도 뒷받침된다. 표면의 특정 높이를 정확히 맞히려는 장치가 계속 예외를 낳았다 —
룩 성벽 홈에서 첫 광선이 빈 공간을 통과(86,400조합 중 2,352회), 재투사가 드물게 반대편 표면 채택(24회),
지지점 직접 사용(966회), 매 프레임 표면 raycast 비용 평균 0.29ms.
**중심 타격으로 바꾸면 이 전부가 사라진다.**

## 1. 타격 지점 — 말 중심 고정

- 적용점 = **`lerp(무게중심, 시각적 중심, STRIKE_HEIGHT_RATIO)`**
  - 무게중심 = `body.worldCom()`
  - 시각적 중심 = 말의 **현재 월드 AABB 중심**
  - `STRIKE_HEIGHT_RATIO` 기본 **1.0**(= 시각적 중심), 조절판 범위 **0 ~ 2**
- **회전이 자연히 생기는 이유**: 체스말은 밑동이 무거워 무게중심이 시각적 중심보다 낮다
  (폰 높이의 39%, 킹 36%). 시각적 중심을 밀면 무게중심 위를 미는 셈이 되어 **앞으로 기우뚱**한다.
  레버 암은 폰 0.057, 킹 0.143이지만 최종 각속도는 관성 모멘트의 영향도 함께 받으므로
  **큰 말일수록 더 많이 회전한다고 일반화할 수 없다.**
  - 비율 0 → 무게중심 정타라 발사 순간의 타격 토크가 0이다. 이후 보드 마찰은 별도 토크를 만들 수 있다.
  - 비율 1 → 시각적 중심을 타격하는 기본값이다.
  - 비율 2 → 비율 1의 두 배 레버 암으로 발사 순간 타격 토크가 두 배다. 최종 전도량은 단조 증가하지 않는다.

비율 1.0·최대 발사 속도에서 실제 Rapier 초기 pitch 각속도는 다음과 같다.

| 종류 | 초기 pitch 각속도 (rad/s) |
|---|---:|
| Pawn | 27.6321 |
| Rook | 12.3891 |
| Knight | 34.0093 |
| Bishop | 29.3246 |
| Queen | 19.8697 |
| King | 22.9192 |

킹은 폰보다 레버 암이 크지만 관성 모멘트도 커서 초기 pitch 각속도는 약 17% 작다.
- **빨간 점은 이 적용점에 그린다.** 말에 대해 고정이며, **WASD로 시점을 바꿔도 움직이지 않는다.**
- 말이 넘어지면 AABB가 바뀌므로 점도 그 자세의 중심으로 따라간다(자세를 따르는 것이지 시점을 따르는 게 아니다).

## 2. 방향 — 시점을 따른다 (유지)

- 수평 방위: `controls.getAzimuthalAngle()` 기준, 말은 카메라가 보는 쪽으로 날아간다.
- 상하 각도: 기존 매핑 유지.
  `u = (피치 − 3°) / 82°`, `고도각 = 60° − 120°u`
  → 낮게 보면 비스듬히 **위로**, 높이 보면 **아래로** 민다.
- 임펄스 = `mass × power × MAX_LAUNCH_SPEED`, 방향 = `normalize(d·cos(e) + up·sin(e))`.
- **HUD 표시**: 세기 · 피치 · 고도각 · Δv · Δω. **타점 높이(%) 표시는 제거**한다(더 이상 조작 대상이 아님).

## 3. 삭제 대상 (슬라이스 4에서 만든 것들)

전부 제거한다. 남겨두면 죽은 코드가 된다.

- 단면 수직 광선(`aimparams.ts` 수직 단면 raycast)
- 실루엣 지지점 계산과 룩 성벽 평행 재투사
- `Triangle.closestPointToPoint` 최종 대체
- 로컬 base→tip 축 유도와 7.5% 인셋
- `hitHeight` 파생·표시·`surfaceRaycastHit` 상태와 HUD의 `표면 raycast / 해석 fallback` 문구
- 위 경로만을 위해 존재하던 캐시·헬퍼

**적응형 근접 카메라 거리와 실제 정점 기반 bounding sphere 캐시는 유지**한다(선택 시 접근에 필요).

## 4. 당구식 턴 카메라 회전 (개발자 요구)

> "클래식 모드로 플레이했을 때 말을 한번 움직였으면, 상대 시점으로 화면이 돌아가서 플레이할 수 있도록 되어 있어.
> 당구식 모드에서도 똑같이 해줘."

- 발사 후 정착이 끝나 턴이 넘어가면, **당구식에서도 카메라가 상대 진영 쪽으로 부드럽게 회전**한다.
- 클래식과 동일한 전환 시간·잠금 규칙을 쓴다(회전 중 선택·조준 잠금).
- 당구식은 공전 중심이 선택된 말이므로, **중심·거리·피치·방위를 단일 0.55초 전환에서 동시에 보간**한다.
- 회전 후 거리는 판 전체가 보이는 거리(미선택 상태 기본값)로 복귀한다.

## 5. 조절판

- `STRIKE_HEIGHT_RATIO` 추가: 슬라이더 + 숫자, 범위 0~2, 기본 1.0.
  설명 문구: "0 = 초기 타격 토크 없음, 1 = 시각적 중심, 2 = 초기 타격 토크 2배".
  이 값은 발사 순간의 레버 암을 뜻하며 이후 마찰 토크나 최종 전도 결과를 보장하지 않는다.
- 슬라이스 4에서 제거했던 `hitHeight`·`hitLateral`은 계속 없다.

## 6. 수락 기준 (게이트2)

**빨간 점 고정**
- [ ] 빨간 점이 말 중심에 있고, **WASD로 시점을 바꿔도 월드 좌표가 변하지 않는다**(6종 × 직립·전도, 방위 1° 간격 전수에서 좌표 분산 ≤ 1e-9)
- [ ] 말 자세가 바뀌면(넘어지면) 그 자세의 중심으로 따라간다
- [ ] **빨간 점 = 실제 임펄스 적용점** (거리 ≤ 1e-9, 로그 확인)

**방향**
- [ ] 피치 3/44/85°에서 고도각 +60/0/−60°
- [ ] A/D로 방위가 바뀌고 화살표가 실시간 갱신
- [ ] 화살표는 여전히 선택 즉시 표시되고 판·말에 가려지지 않는다

**회전**
- [ ] `STRIKE_HEIGHT_RATIO` 0에서 발사 직후 각속도 ≈ 0 (≤ 1e-6)
- [ ] 1.0에서 6종 모두 발사 직후 0이 아닌 pitch 방향 각속도가 생기며 위 실측표와 일치한다
- [ ] 값 변경이 재시작 없이 즉시 반영

**턴 카메라**
- [ ] 당구식에서 발사·정착 후 카메라가 상대 방위로 회전하고 판 전체가 보이는 거리로 복귀
- [ ] 당구식과 클래식 모두 단일 0.55초 전환을 사용한다
- [ ] 회전 중 선택·조준 잠금, 잔여 상태 없음
- [ ] 클래식 동작 회귀 없음
