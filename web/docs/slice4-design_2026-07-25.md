## 0. 개발자 피드백 — 슬라이스 3 조준 UI 폐기

> "세기를 100%로 해도 타격이 안 될 때도 있고, 화살표가 안 나올 때도 있고,
> 퍼센테이지를 조절해서 하는 건 너무 직관적이지 않은 조작법이라 알까기를 하는 재미가 없어."

**슬라이더 3종 + 세기 바를 폐기한다. 보는 방향이 곧 조준이 된다.** 요구는 1 → 2 → 3 순서로 구현한다.

> **v1 → v2 정정**: ①피치↔고도 매핑이 반대였음 ②A/D로는 좌우 타점 레버암이 안 생김 → `hitLateral` 폐기
> ③OrbitControls damping이 키 회전의 프레임 독립성을 깨뜨림 ④선택 즉시 화살표를 위한 preview 상태 누락
> ⑤빨간 점을 별도 공식으로 만들면 실제 적용점과 어긋남 ⑥빨간 점 vs 공전 입력 우선순위 미정의
> ⑦발사 실패를 조용히 버리는 계약 유지 ⑧⑨가림 처리 방식·raycast 간섭 ⑩ArrowHelper renderOrder는 자식에 줘야 함
> ⑪초기 타점 50% 고정 ⑫정리 경로 일원화 ⑬기준 정량화

## 1. WASD 시점 조작 (요구 1)

마우스 좌클릭 드래그 시점 조작은 **그대로 유지**하고 키보드를 추가한다.

- **A / D** — 수평 공전 좌/우
- **W / S** — 카메라 피치. **W = 카메라를 올린다(= 내려찍기), S = 내린다(= 쳐올리기)**
- 누른 동안 연속 회전, `CAM_KEY_DEG_PER_SEC`(초기 90°/s), **실제 경과 시간(TIME_SCALE 아님)** 기준.
- **프레임 독립성 (지적 3 — 높음)**: 현재 `scene.ts`는 OrbitControls damping을 켜 두었고,
  `rotateLeft()`/`rotateUp()`은 매 프레임 `dampingFactor`만 적용하고 잔량을 감쇠시킨다.
  단순히 `90° × delta`를 넘기면 30/60/165fps 결과가 달라진다.
  → **조준 모드에서는 damping을 끄고, 구면좌표(theta/phi)를 `rate × wallDelta`로 직접 한 번만 적분한다.**
- 키 상태는 `Set<code>`로 유지하고 `blur`·`visibilitychange`에서 비운다.
- 숫자 입력 필드에 포커스가 있으면 WASD를 가로채지 않는다.
- 클래식 모드에서도 A/D는 동작(상하는 클래식 계약상 고정).

## 2. 직접 조준 (요구 2) — 핵심

### 2-1. 카메라 피치가 곧 타점과 고도 (지적 1 — 높음)

**별도 `aimElevation` 상태를 두지 않는다. 카메라 피치에서 직접 파생한다.**

```
u            = (cameraPitch − 3°) / (85° − 3°)      // 0 ~ 1
aimElevation = 60° − 120° × u                       // +60(쳐올림) ~ −60(내려찍기)
hitHeight    = u                                    // 0(바닥) ~ 1(꼭대기)
```

| 카메라 피치 | u | 고도각 | 타점 높이 | 감각 |
|---|---|---|---|---|
| 3° (낮게 봄) | 0 | **+60°** | 0% | 밑동을 위로 쳐올림 → 뜬 궤적 |
| 44° | 0.5 | 0° | 50% | 정면 수평 타격 |
| 85° (위에서 봄) | 1 | **−60°** | 100% | 꼭대기를 내려찍음 |

v1은 이 대응을 반대로 적었다. 카메라는 판 아래로 갈 수 없으므로 **낮게 볼수록 쳐올리는** 역방향 매핑이 맞다.

### 2-2. 좌우 타점 폐기 (지적 2)

A/D로 카메라를 돌리면 발사 방향 `d`와 적용점 `−d`가 함께 돌 뿐이라 `s = d × up` 방향 오프셋은 **항상 0**이다.
즉 이 모델에서 별도 좌우 타점은 만들어지지 않는다. 개발자가 말한 "좌우 타점"은 **말의 어느 둘레에서 치는가**이고
그것은 A/D 방위로 이미 충족된다. → **`hitLateral`과 사이드 스핀 표현을 삭제한다.**
진짜 좌우 오프셋이 나중에 필요하면 Q/E를 별도로 추가한다(이번 범위 아님).

### 2-3. 상태 모델 (지적 4 — 높음)

```
idle → selected(preview: power 0, 화살표·빨간 점 표시)
     → charging(빨간 점 포인터 캡처, 세기 상승)
     → launch | cancel → idle
```

**선택 상태에서 항상 방향·적용점·최소 길이 화살표를 계산**한다. 세기 조건은 화살표 표시에 관여하지 않는다.
v1처럼 세기 입력 시점에만 조준 상태를 만들면 화살표는 여전히 안 나온다.

### 2-4. 빨간 점 = 실제 적용점 (지적 5 — 높음)

- **`computeStrikeSolution()`을 한 번만 계산하고, 빨간 점은 그 `applicationPoint`를 그대로 복사한다.**
  **역산하는 두 번째 공식을 만들지 않는다.** 표시와 물리가 어긋나면 안 된다.
- "말 표면"을 만족시키려면 **선택된 메시만 대상으로 카메라에서 조준 목표점 방향으로 raycast**해
  가장 가까운 교차점을 쓴다. AABB 최대 폭(`max(width, depth)/2`)은 Knight처럼 x/z가 다르거나
  90° 넘어져 높이 1.0이 수평 폭이 된 말에서 점이 메시 밖에 뜨거나 안에 박힌다.
- 그리기: `depthTest = false`, 높은 `renderOrder`로 **말에 가려지지 않게** 한다.
- **초기 선택 시 (지적 11)**: 카메라 피치 **약 44°**, 고도 0°, 타점 **50%**(중앙), 좌우 없음.
  조절판에서 `hitHeight`·`hitLateral` 슬라이더는 **제거**하고, 초기 피치와 WASD 회전 속도만 남긴다.

### 2-5. 세기와 발사 (지적 6·7 — 높음)

- **빨간 점을 누른 뒤 아래로 드래그 → 세기**, 손을 떼면 발사. `power = clamp((y − startY) / MAX_DRAG_PIXELS, 0, 1)`
  (**아래 방향만** 유효).
- **입력 우선순위**: 캡처 단계에서 **빨간 점을 최우선 hit-test**한다.
  - 히트 영역은 **화면 기준 최소 24px 반경**의 투명 영역(작은 3D 점을 정확히 누르게 하면 모바일 조작감이 무너진다).
  - 히트 시 `preventDefault` + `stopImmediatePropagation` + pointer capture + **OrbitControls·WASD 잠금**.
  - 미히트 시 이벤트를 그대로 OrbitControls로 넘긴다.
  - 규칙 고정: **빈 공간 탭 = 선택 해제 / 빈 공간 드래그 = 공전 / 선택 말 클릭 = 선택 유지 / 빨간 점 클릭 = 충전.**
  - 충전 중 추가 포인터 차단. 평상시 두 손가락 pinch는 유지.
- **발사 성공 여부를 반환한다 (지적 7)**: `queueLaunch(): boolean`(또는 결과 객체).
  **성공했을 때만** 선택 해제와 펄스를 실행하고, 실패하면 **조준을 유지한 채 원인을 화면·콘솔에 표시**한다.
  개발자가 겪은 "100%인데 발사 안 됨"의 유력 원인은 세기 바 밖에서 `pointerup` 시 취소되는 경로였다.
  → **포인터가 캔버스 안에 있으면 빨간 점 밖에서 놓아도 발사**되어야 한다.
- **세기 바 UI 제거.** 조준 슬라이더도 주 조작에서 제거.

### 2-6. 가림 처리 (지적 8·9)

- **`visible = false` + 숨김 ID `Set`만 사용한다.** 투명 재질 교체는 `depthWrite`·정렬·그림자·복구 문제가 붙고,
  무엇보다 백·흑 각 16개가 **공유 재질**을 쓰므로 재질을 건드리면 같은 색 전부가 투명해진다.
- 판정 계약을 좁힌다: **카메라 → 빨간 점 ray에 먼저 맞는 말만 숨긴다.** "실루엣을 조금이라도 가림"은
  바운딩 구 하나로 정확히 판정할 수 없다.
- **Three.js Raycaster는 `visible=false`도 교차시킨다.** 따라서
  - 말 **선택** raycast에는 숨겨진 말을 그대로 포함해 기존 선택 규칙(관통 금지)을 지키고,
  - **빨간 점 hit-test는 선택 raycast와 분리**해 최우선으로 처리한다.
- 선택 해제·모드 전환·발사·말 제거·오류 시 **전부 복원**한다.

## 3. 화살표 수정 (요구 3)

**원인(코드 확인)**
1. `arrow.visible = activeAim.normalizedPower > 0` (`aim.ts:257,296`) — 세기 입력 전에는 안 그린다.
2. `bounds.min.y + 0.035`에 놓고 임펄스 방향 그대로 그린다(`aim.ts:396-401`) — 고도가 음수면 판을 뚫고 가려진다.

**수정**
- 조건 제거(§2-3 preview 상태에서 항상 표시).
- 시작점을 빨간 점으로 올린다.
- **ArrowHelper는 부모에 `renderOrder`를 줘도 효과가 없다 (지적 10)** — 실제 렌더 대상은 자식 `line`과 `cone`이다.
  → **`arrow.line.material`과 `arrow.cone.material` 양쪽에 `depthTest = false`, `depthWrite = false`를 설정하고,
  두 자식에 직접 `renderOrder`를 준다.** 순서는 **선택 고리 < 화살표 < 빨간 점**으로 숫자 고정.

## 4. 정리 경로 일원화 (지적 12)

턴이 `ready`가 아니게 되거나 선택된 바디가 제거·기상하면 조준을 취소한다.
**숨김 목록 복원·포인터 캡처 해제·WASD 키 Set 비우기·카메라 잠금 해제를 하나의 `cancelInteraction()`에서 처리**한다.
튜닝 깨우기, 말 제거, 모드 전환, `blur`, `visibilitychange` 모두 이 경로를 탄다.

## 5. 파일 구조

기존 모듈 유지. `aimparams.ts`를 슬라이더 UI 대신 **WASD 조준 상태**(피치 파생 고도·타점·세기)로 개편.
`input.ts`에 키보드·빨간 점 우선 hit-test 추가. `scene.ts`에 가림 처리 추가. 새 모듈 없음.

## 6. 수락 기준 (게이트2 — 정량, 지적 13)

**WASD 시점**
- [ ] **2초간 키를 유지했을 때 30/60/165fps 회전각 차이 ≤ 0.1°**
- [ ] 여러 키 동시 입력 동작, 숫자 입력 필드 포커스 중 시점 고정, `blur` 후 키 상태 잔여 없음
- [ ] 마우스 드래그 시점 조작 회귀 없음

**조준**
- [ ] 피치 3/44/85°에서 고도각이 각각 +60/0/−60°, 타점 높이가 0/50/100%
- [ ] **빨간 점과 실제 발사 적용점의 거리 ≤ 1e-6** (로그로 두 값 비교)
- [ ] 빨간 점과 렌더 메시 표면 거리가 허용치 내(6종 × 직립·90° 전도)
- [ ] 초기 선택 시 피치 ≈44°, 타점 50%
- [ ] 빨간 점이 말에 가려지지 않음

**화살표**
- [ ] **선택 즉시 표시**(세기 0에서도), 시점 회전 시 실시간 갱신
- [ ] **6종 × 직립·전도 × 고도 −60/0/+60 전 조합에서 화살표가 화면에 보임**(픽셀 확인)

**세기·발사**
- [ ] **100% 드래그를 화면 중앙과 캔버스 가장자리에서 각각 반복해 모두 발사**
- [ ] 빨간 점 밖에서 놓아도 캔버스 안이면 발사됨
- [ ] 충전 중 카메라가 마우스·WASD 어느 쪽으로도 안 움직임
- [ ] `Esc`·캔버스 밖·`pointercancel`·capture 상실·멀티터치·`blur`에서 **발사 0회**
- [ ] **발사 큐가 거절되면 선택이 조용히 사라지지 않고 원인이 표시됨**

**가림**
- [ ] 카메라→빨간 점 ray에 먼저 맞는 말만 숨겨지고, 해제 후 **32개 전부 `visible = true`**
- [ ] 같은 색 다른 말이 함께 투명해지지 않음
- [ ] 숨겨진 말도 물리·충돌·선택 판정에 그대로 참여

**기타**
- [ ] 평상시 터치 pinch 유지, 클래식 모드 회귀 없음
- [ ] 콘솔 에러 0, `npm run build` 성공, `unity/`·`resource/` 무변경
